# Деплой AZRAIL — порядок и что делать, если упадёт

Проверено перед сборкой: `npm ci` проходит, типы компилируются, 447 теста
зелёные, сборка собирается, все девять классов агентов есть в бандле.

Воркер `azrail-os` в аккаунте сейчас — заглушка **без Durable Objects**,
миграции ни разу не применялись. Значит наша миграция `v1` ляжет чисто,
конфликта состояний не будет.

---

## Порядок

**1. Пустой репозиторий на GitHub** — без README, без .gitignore, совсем
пустой. Иначе первый push упрётся в расхождение историй.

**2. Пуш из Termux**

```bash
pkg install git          # если ещё нет
cd azrail-os
bash push-to-github.sh   # спросит URL репозитория и токен
```

Токен нужен с правом `repo`.

**3. Связать с Cloudflare**

Dashboard → Workers & Pages → `azrail-os` → Settings → Build →
Connect to Git → выбрать репозиторий и ветку.

Команда деплоя: `npx wrangler deploy`

**4. Секрет доступа**

Settings → Variables and Secrets → Add → тип **Secret**:

- Имя: `AZRAIL_TOKEN`
- Значение: любая длинная случайная строка

Без него API отдаёт 503 — так задумано: лучше отказ, чем открытый доступ.

**5. AI Gateway**

Dashboard → AI → AI Gateway. Если шлюза нет — создать.
Имя шлюза должно совпадать с `AI_GATEWAY_ID` в `wrangler.toml`
(сейчас там `default`).

Без него доступны только модели Cloudflare, и **четыре типа задач
останутся на одной модели без запасной** — самопроверка покажет их красным.

**6. Таблицы в D1 — ОБЯЗАТЕЛЬНО, иначе чат и миссии упадут**

Схема НЕ применяется деплоем сама. Без этого шага `/api/chat`,
`/api/mission` и `/api/conversations` отвечают ошибкой «no such table»
на первом же обращении.

```bash
npx wrangler d1 execute azrail-db --remote --file=./schema.sql
```

Все `CREATE TABLE` идут с `IF NOT EXISTS`, поэтому повторный запуск
безопасен и ничего не затирает.

**Если таблицы уже создавались РАНЬШЕ этой версии** — в `missions`
не хватает колонки `finished_at` (она добавлена позже, а `CREATE TABLE
IF NOT EXISTS` существующую таблицу не меняет):

```bash
npx wrangler d1 execute azrail-db --remote \
  --command="ALTER TABLE missions ADD COLUMN finished_at TEXT"
```

Ошибка «duplicate column name» здесь означает, что колонка уже есть —
это нормально, идём дальше.

**7. Потолок расходов — поставить ДО перехода на платный план**

На бесплатном плане не нужен: там переплата невозможна, Cloudflare просто
перестаёт обслуживать. Нужен ровно с того дня, когда план станет платным.

Settings → Variables → `AZRAIL_WRITE_BUDGET` (обычная переменная, не секрет).
По умолчанию 5000 записей в час. Нормальная миссия укладывается в 60.

Причина: Cloudflare берёт деньги за каждую операцию записи и НЕ ДАЁТ
поставить жёсткий потолок расходов — о превышении узнают по счёту.

**8. Первый запуск**

Открыть адрес воркера → блок «Доступ» → вставить токен →
кнопка **«Проверить систему»**.

## Если упадёт

### Сборка в CI

**`npm ci` не проходит** — расхождение `package.json` и `package-lock.json`.
Проверено локально, что синхронны; если CI ругается, скорее всего версия
Node. В настройках сборки Cloudflare выставить Node 20 или новее.

**Ошибки типов** — локально `npx tsc --noEmit` чист. Если в CI иначе,
значит не установились `devDependencies`: проверить, что команда сборки
не содержит `--production`.

### Деплой

**`Unknown compatibility flag: experimental`** — вопрос ЗАКРЫТ, но раздел
оставлен на случай регрессии.

Это уже случилось (2026-08-23) и решено: Cloudflare отклоняет флаг на
уровне API кодом 10021 — `"experimental is experimental and cannot yet be
used in Workers deployed to Cloudflare"`. Не гипотеза, не "может быть не
примут" — принимают всегда одинаково, с отказом. Флаг убрали из
`wrangler.toml`, оставив `"nodejs_compat"`, передеплоили — прошло.
Самотест подтвердил: `subAgent()` поднимает всех девять агентов и без
флага, хотя исходник SDK текстом своей ошибки утверждает обратное.

**Если эта ошибка появилась снова** — значит `"experimental"` откуда-то
вернулся в `compatibility_flags` (например, из старого ZIP-бэкапа при
восстановлении файлов — конкретный такой случай уже был). Это не новая
загадка, а известная регрессия: открыть `wrangler.toml`, убрать
`"experimental"`, оставить только `"nodejs_compat"`, закоммитить, пушить
заново. Расследовать заново не нужно.

**Ошибка миграции Durable Object** — не должна возникнуть (воркер сейчас
без DO), но если появится: НЕ менять номер миграции руками. Прислать текст.

### Самопроверка

**Все восемь агентов красные, в тексте ошибки — `"experimental"`**

Раньше это означало «добавь флаг». Теперь наоборот: флаг уже проверен и
однозначно ломает сам деплой, добавлять его нельзя. Если ошибка про
`"experimental"` всплыла на уже работающем деплое (без флага в
`wrangler.toml`) — значит что-то в самом SDK или рантайме изменилось
относительно того, что было верно 2026-08-23, и это повод разбираться
заново, а не откатывать старое решение. Прислать точный текст ошибки и
версию пакета `agents` из `package.json`.

**Один-два агента красные, остальные зелёные** — это уже не про флаг,
а про конкретного агента. Хороший, локализуемый случай.

**Агент зелёный, но `storageReadable: false`** — поднялся, а хранилище
не отвечает. Отдельный вид поломки, спрятан не будет.

**Красный шаг D1** — цепочка `users ← projects ← остальное`. Строка
пользователя `system` в базе уже есть, проверено. Если всё же красный,
прислать текст ошибки.

**Маршруты моделей красные с пометкой «БЕЗ ЗАПАСНЫХ»** — не поломка,
а предупреждение: не задан `AI_GATEWAY_ID`. Работать будет, но без
подстраховки.

## Что смотреть в первые дни

`wrangler tail` — логи структурные:

- `router.chose` — какую модель реально взяли и почему
- `router.fallback` — где ушли на запасную
- `router.empty_response` — модель ответила пустотой
- `model.exhausted` — исчерпан лимит, модель отстранена
- `task.finished` — итог задачи со временем выполнения

AI Gateway начнёт копить настоящие цифры: стоимость, задержки, доля
ошибок по моделям. Через пару дней это будет первый **факт** о системе,
а не предположение.

Политика выбора моделей вынесена в одно место —
`src/lib/model-registry.ts`, блок `ROUTING_POLICY`. Менять там.
