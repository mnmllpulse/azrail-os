# Подключения MCP — Unified 1.3

Реализован серверный клиент Streamable HTTP для версий MCP `2025-11-25` и `2025-06-18`. Это рабочий механизм для совместимых, настроенных серверов. Поддержка конкретного сервиса подтверждается отдельным живым тестом; логотип сервиса и подписка Canva Pro не дают приложению OAuth-доступ автоматически.

## Подготовка оператором

1. Выберите доверенный MCP endpoint и проверьте его протокол и условия использования. В 1.3 нет подключения произвольного URL из запроса модели.
2. Добавьте политику в Repository Variable `MCP_SERVERS`: JSON-массив объектов с полями ниже. Дефолт `[]` оставляет каталог пустым.
3. Создайте один постоянный `INTEGRATION_KEY`: 32 криптографически случайных байта в base64. Сохраните в GitHub Actions Secrets и защищённой резервной копии. Не меняйте его при каждом deploy: существующие шифротексты потребуют старого ключа. Автоматической ротации с перешифрованием пока нет.
4. Для OAuth зарегистрируйте отдельный клиент приложения и URI `https://<ваш-домен>/api/connectors/oauth/callback` для каждого используемого домена. Это отдельный callback, отличный от входа `/auth/callback`.
5. Для confidential client поместите JSON-словарь `{policyId: clientSecret}` в Secret `MCP_OAUTH_SECRETS`. Поддержан `client_secret_post`; значения не входят в `MCP_SERVERS` или frontend.
6. Deploy применяет миграцию 009 и передаёт конфигурацию серверу. Не публикуйте токены в репозитории, HTML или промптах.

| Поле политики | Содержание |
|---|---|
| `id` | Уникальный идентификатор из букв, цифр, `_ . -`, до 128 символов |
| `name` | Название сервиса, до 80 символов |
| `url` | Точный HTTPS endpoint без query, fragment, userinfo и нестандартного порта |
| `auth` | `none`, `bearer` или `oauth` |
| `readTools` | Только проверенные оператором инструменты чтения без изменений; пустой массив требует подтверждения всех вызовов |
| `blockedTools` | Явно запрещённые имена инструментов |
| `dailyCalls` | 0–1000 операций в сутки UTC на пользователя и сервис; discovery тоже расходует единицу |
| `oauth.clientId` | Зарегистрированный client ID |
| `oauth.authorizationUrl` | Точный доверенный HTTPS endpoint авторизации |
| `oauth.tokenUrl` | Точный доверенный HTTPS endpoint обмена кода |
| `oauth.scopes` | Минимальный набор согласованных scopes |

В allowlist не следует включать серверы с ненадёжным DNS или произвольным сетевым проксированием. Проверки имени и запрет redirects не являются DNS pinning или полным сетевым firewall. OAuth metadata discovery и динамическая регистрация клиента в 1.3 не реализованы.

## Сценарий пользователя

1. Войти в AZRAIL → «Подключения» → выбрать настроенный сервис.
2. Для Bearer ввести личный токен, для OAuth пройти вход и согласовать scopes у провайдера. Доступ хранится с привязкой к вашему аккаунту, а не общим ключом всех пользователей.
3. Нажать «Проверить соединение». Сервер выполняет initialize и tools/list и сохраняет схему с хешем. Каталог считается свежим 24 часа.
4. Задать задачу агенту либо открыть «Найти инструмент». Подбирается максимум пять схем. Это лексический поиск по названию/описанию, не семантический RAG.
5. Для внешнего изменения открыть «История и ожидающие действия»: проверить название подключения, инструмент и точные параметры; подтвердить или отменить.
6. Возобновить ожидающую миссию. Агент читает `connector_status` либо получает уже сохранённый результат; подтверждение не выдаётся моделью самой себе.
7. При необходимости отключить сервис: локальный секрет удаляется, новые вызовы запрещаются, подготовленные действия отменяются. Уже отправленное действие может завершиться. Токен у самого провайдера нужно отзывать отдельно.

OAuth Code + PKCE S256 связан с пользователем, origin, одноразовым state и HttpOnly cookie. Access token шифруется AES-256-GCM. Текущая реализация не хранит refresh token и не обновляет доступ автоматически: после expiry нужно подключить сервис заново.

## Повторы, цена и границы

Параметры подготовленного действия неизменны. Подтверждение привязано к revision подключения, политике, каталогу и аргументам; срок — 10 минут. Изменение схемы перед исполнением отменяет прежний допуск. На аккаунт допускается до 30 активных подключений и 20 незавершённых OAuth-процессов.

CAS `prepared → running` происходит до внешнего вызова. Дубликат не отправляется. Потеря ответа после отправки даёт `uncertain` и удерживает резерв. Перезапуск Worker не означает, что удалённое действие не состоялось. Полная автоматическая сверка с удалённой системой и восстановление зависшего `running` пока не реализованы; нужны ручная проверка у провайдера и серверная сверка. Нельзя вручную сбрасывать статус и повторять действие вслепую.

Сбой settlement после сохранения результата не скрывает результат и не вызывает повтор: резерв остаётся удержанным, повторное чтение через execute завершает учёт без обращения к провайдеру.

`dailyCalls` — счётчик операций, а не долларовый hard cap. Одна операция может включать handshake, несколько страниц tools/list и tools/call. Тарифы внешнего сервиса определяет его провайдер. Настройка «Сторонние AI-модели OFF» относится к AI router; она не отключает все подключённые SaaS и не ограничивает их счета. Платные или модельные MCP tools нельзя объявлять безопасными только на основании `readOnlyHint`.

Поддерживаются JSON и SSE-ответы, до 512 КиБ на ответ, до 200 tools и 5 страниц discovery. Нет stdio, серверного sampling, resumable SSE, произвольного computer use и гарантии совместимости с иными версиями MCP. Внешние описания/результаты считаются данными, не инструкциями для повышения полномочий.

## API и проверка

- `GET/POST /api/connectors` — каталог и подключения.
- `POST /api/connectors/oauth/start`; `GET /api/connectors/oauth/callback` — OAuth.
- `POST /api/connectors/:id/discover`; `DELETE /api/connectors/:id`.
- `GET /api/connectors/tools?q=...` — до пяти схем.
- `POST /api/connectors/prepare` с `Idempotency-Key`.
- `GET /api/connectors/calls`; `GET /api/connectors/calls/:id`.
- `POST /api/connectors/calls/:id/execute` с `{confirm:true}` для изменений.
- `POST /api/connectors/calls/:id/cancel` — только ещё не отправленные действия.

Доказательства локального поведения: `tests/connectors.test.ts`, `tests/connector-oauth-design.test.ts`. Провайдер в этих тестах имитируется; D1 SQL исполняется реальным SQLite.

Официальные основания протокола: [Transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization). Реализация ограничена явно перечисленными возможностями.
