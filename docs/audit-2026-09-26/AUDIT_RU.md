# AZRAIL OS 0.8.1 — повторный аудит и исправления

Дата: 26 сентября 2026. Основа: архив `azrail-os-0.8.0-ultimate.zip`, 191 файл. Сначала проверены CRC ZIP и SHA-256 всех файлов по его манифесту; рабочая копия совпадала с исходным архивом.

Результат: исправлены перечисленные ниже дефекты, добавлены проверки воспроизведения, выпущен архив 0.8.1. Это проверка исходников и локального поведения. Она не означает, что все возможные ошибки найдены, все архитектурные модули внедрены или Cloudflare production проверен.

## Что случилось с ultimate.html на телефоне

`ultimate.html` — файл, а не папка. В 0.8.0 он подключал оформление и обработчики абсолютными ссылками `/ultimate.css` и `/ultimate.js`. При открытии одного файла из ZIP через Android `content://` соседние ресурсы не находились. Поэтому на скриншоте отображались обычный белый фон, стандартные кнопки и текст без оформления.

В 0.8.1 стили и JavaScript встроены в сам HTML. Отдельные `ultimate.css` и `ultimate.js` оставлены исходниками; `npm run build:ui` обновляет встроенные копии. Автотест проверяет их совпадение. Теперь для просмотра оформления достаточно одного HTML, без сервера, внешних шрифтов и CDN. Если файловый менеджер отключает JavaScript, оформление всё равно находится внутри документа; для кнопок следует открыть HTML в браузере.

Локальная страница показывает статус «Локальный просмотр». Она не имитирует работу моделей и не отправляет ключ на произвольный сервер. В настройках можно ввести HTTPS-адрес своей установленной системы и открыть `/ultimate.html` на ней. Ключ вводится уже на странице системы.

Добавлены уточнение во время миссии, скачивание её реального результата в JSON, повторная проверка статуса и восстановление последней миссии после перезагрузки той же вкладки. Пункт «Проекты» доступен на мобильном экране. Новая вкладка не обязана иметь sessionStorage предыдущей — сохраните номер миссии или результат.

| 1 | Высокий | Ultimate терял CSS/JS при открытии одного файла из ZIP | Самодостаточный HTML; проверяется точное включение исходных CSS/JS, отсутствие обязательных внешних ресурсов |

## Проверки выпуска

- `npm run check`: сборка самодостаточного UI, TypeScript strict и **1052 теста в 46 файлах — успешно**.
- 48 дополнительных тестовых случаев относительно 0.8.0. Часть старых тестов, проверявших текст исходника или примитивные SQL-заглушки, переведена на актуальные контракты. Для переходов статуса и очереди используется настоящий SQLite.
- Оба entry point, `src/index.ts` и `src/index.free.ts`, собраны **локально через esbuild**, без вызова Wrangler и без отправки кода. Gzip: 539481 и 538400 байт соответственно на момент проверки.
- Все четыре HTML-страницы проверены на дубли ID, отсутствующие обязательные локальные JS/CSS и синтаксис встроенных скриптов. Ошибок в этих проверках нет.
- JS/MJS проходят `node --check`; TOML читается парсером.
- Миграция проверена на SQLite с исторической формой таблицы missions, без result_json и без mission_hints. Существующая строка сохраняется; режим инспекции не выполняет DDL.
- Повторная упаковка проверяется CRC, соответствием SHA-256 манифесту и отсутствием временных файлов и секретов.

В `CHECK_RESULTS.json` — машинная сводка; `CHANGED_FILES.json` — изменения относительно оригинала; `RELEASE_FILES.json` в корне — SHA-256 файлов выпуска, кроме самого манифеста.

## Что не проверено на реальной платформе

1. В этой среде нет установленного браузера/Agent Browser. Тесты Ultimate исполняют настоящий JavaScript с подменёнными DOM, HTTP и хранилищем; это не визуальный прогон на Android. Причина отсутствия оформления устранена в структуре файла, но конкретный просмотрщик телефона отдельно не проверен.
2. Cloudflare production, реальный AI Gateway, платежи провайдерам, Docker и полный сценарий миссии через живой SDK здесь не запускались. Локальная сборка не заменяет такую проверку.
3. Wrangler dry-run в предыдущем проходе был остановлен автоматической проверкой разрешений из-за возможной отправки собранных данных в `sparrow.cloudflare.com`. Здесь он не повторялся; выполнена независимая локальная сборка.
4. Зависимости не обновлялись. Использованы версии lockfile, включая Workers types 4.20260702.1. Получение свежего пакета типов не завершилось; свежий сетевой CVE-аудит не заявляется. Старый отчёт npm audit относится к 0.8.0.
5. Платёжный резерв — консервативная оценка текстовых токенов. Итог берётся из usage провайдера. Долг уже отправленного запроса, недоступный usage, нетекстовые услуги и стоимость Workers/R2/Containers не превращаются в «нулевой счёт» переключателем моделей.
6. Состояние внешнего действия после сетевого разрыва может остаться неопределённым. Автоповтор такого checkpoint запрещён; проверка администратором остаётся необходимой. Гарантия exactly-once для всех внешних сервисов не заявляется.
7. Sandbox-команды выполняются во временной файловой системе. Двусторонний перенос произвольных изменений команды обратно в R2 и полноценный локальный Free runner пока не реализованы. Проверка миссии использует свежую папку; полноценная изоляция сети и политика установок пакетов требуют отдельного внедрения.

## Совместимость данных и порядок обновления

1. Остановите активные миссии и сохраните независимые копии D1 и R2. Применяйте обновление сначала к тестовой установке.
2. Выполните `npm ci` и `npm run check` на Node.js 24.
3. Проверьте выбранный конфиг и ресурсные ID. `wrangler.toml` содержит Paid Sandbox; `wrangler.free.example.toml` предназначен для отдельной Free-установки.
4. Подготовьте план: `npm run db:migrate -- --remote --config wrangler.toml`. Команда только инспектирует базу и пишет SQL-план локально.
5. Примените проверенный план: `npm run db:migrate -- --remote --apply --config wrangler.toml`. Скрипт сначала экспортирует D1, затем применяет миграции. Для Free укажите собственный Free-конфиг. На новой пустой базе достаточно актуального `schema.sql`.
6. **Миграция 007 обязательна для новой очереди подсказок.** Старые недоставленные KV-подсказки автоматически не переносятся: после обновления отправьте их заново. До публикации кода убедитесь, что новая схема применена.
7. Проверьте старые R2-файлы с `%xx` и нестандартными именами. В 0.8.0 уже мог образоваться смешанный набор сырых и URL-кодированных имён. Исправление не угадывает намерение автора старого манифеста. Нужна сверка имён по исходному проекту; старые данные не удаляются.
8. Новые backup v2 и snapshots-v2 сохраняют байты и логические пути. Откат к старому Worker 0.8.0 не даёт поддержки нового формата backup v2; сохраните прежние копии и используйте 0.8.1 для чтения новых копий.
9. После отдельной публикации проверьте живые вход/выход, создание миссии, отмену, подсказку, повторную отправку, восстановление, OFF и согласованный платный бюджет. Сам архив ничего не разворачивает.

## Что ещё остаётся разработать

Ultimate — простой рабочий экран существующего ядра. Графическая генерация, отдельный голосовой адаптер, синтез аудио и Beatport pipeline, большая часть 33 интеграций, полноценные Studio/Lab, доказанные сравнения с конкурентами и заявка на мировой №1 остаются пунктами архитектуры и Roadmap 0.8.0. Кнопка студии не означает, что её движок уже подключён. В текущем интерфейсе эти состояния обозначены прямо.
