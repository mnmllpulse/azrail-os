Сильная часть проекта. Отдельно отмечу качественные модули:

- `model-registry.ts` (464) + `model-router.ts` (562) — выбор модели по *возможностям*, а не по имени. Каждая запись с источником данных.
- `resilience.ts`, `idempotency.ts`, `outbox.ts`, `quota.ts`, `mission-concurrency.ts` — надёжность сделана всерьёз.
- `secret-scan.ts`, `cve-scan.ts`, `safe-path.ts`, `zip-reader.ts` (zip-bomb) — безопасность не для галочки.

### 1.6 HTTP-слой (`src/index.ts`, 1192 строки)

~55 маршрутов, разобранных **цепочкой из 55 `if (url.pathname === …)`**.
Порядок объявления = приоритет. Добавление маршрута в неверное место — молчаливая регрессия.
Авторизация двухуровневая: bootstrap-токен `AZRAIL_TOKEN` → роль `administrator`, либо ключ `az_<64hex>` → аккаунт из D1. Реализовано корректно (`authenticate` → `authorizeRequest`).

### 1.7 Фронтенд — 🔴 главная проблема проекта

| Файл | Строк | Дизайн-система | Хранилище токена | API, которое знает |
|---|---|---|---|---|
| `index.html` | **3790** (2444 из них — инлайн-JS) | Geist/Space Grotesk, `#020204`, фиолет | своё | 17 эндпоинтов |
| `classic.html` | **1711** | Syne/JetBrains, `#09070D`, «реестр» | своё | 5 эндпоинтов (legacy `/api/task`) |
| `ultimate.html` | 161 (+`.css` 7 + `.js` 131) | system-ui, `#09080f`, `--accent:#b497f4` | `azrail_ultimate_token` | 5 эндпоинтов |
| `control.html` | 12 (+`.js` 23) | голый system-ui, без сетки | своё | 11 эндпоинтов |

**Это четыре разных продукта в одной папке.** Три шрифтовые пары, три палитры, четыре независимых хранилища токена (вход в одном окне не даёт входа в другом), четыре разных способа показать ошибку.

Ни один из четырёх не покрывает API целиком:
- `index.html` не знает про `/api/routing-settings`, `/api/model-catalog`, `/api/admin/*`, `/api/backups`, `/api/metrics`, `/api/projects/:id/memory|versions|history`, `/api/mission/recover`.
- `ultimate.html` умеет только миссию — ни чата, ни истории, ни файлов.
- `control.html` — единственный, кто видит биллинг и аккаунты, и выглядит как форма из 2003 года.
- `classic.html` — единственный, кто умеет «студии» (UI Agent, Git Agent, QA Agent), и он же самый заброшенный.

### 1.8 Тесты (46 файлов, 1052 теста)

`regressions.test.ts` — **3165 строк**, свалка. `logic.test.ts` — 976.
`frontend.test.ts` и `ultimate-ui.test.ts` — статический разбор CSS/HTML и исполнение скрипта в `node:vm` с самописным DOM. Изобретательно, но **это не браузер**: не ловит layout, не ловит реальные события, не ловит ничего из `index.html` (там проверяется только CSS-каскад).
Нет: e2e (Playwright), нет визуальных регрессий, нет a11y-прогона, нет замеров производительности.

### 1.9 Безопасность — точечные замечания

1. `public/_headers` задаёт `X-Frame-Options: DENY` — правильно для прода, но **ломает предпросмотр в iframe** (Arena/Cloudflare Preview). Нужен `frame-ancestors` в CSP вместо жёсткого DENY, с исключением для собственных превью-доменов.
2. **CSP отсутствует полностью.** При 2444 строках инлайн-JS в `index.html` подключить CSP без `unsafe-inline` невозможно — ещё один довод вынести скрипты в файлы.
3. `CORS_ORIGIN = "*"` в `wrangler.toml`. С Bearer-токеном это не даёт кражи сессии (нет cookie), но открывает API любому origin. Для прода надо сузить.
4. Токен хранится в `sessionStorage` — уязвим к XSS. При инлайн-JS без CSP риск не нулевой.

## 2. Слабые стороны — по убыванию ущерба

| # | Слабость | Почему это дорого |
|---|---|---|
| **1** | **Четыре несвязанных UI** | Пользователь не может пройти сценарий целиком: задача в одном окне, биллинг в другом, студии в третьем, и везде заново логин. Это убивает продукт вернее любого бага. |
| **2** | **~40 % API не имеет интерфейса** | Написан и оттестирован биллинг, память проекта, версии, бэкапы, метрики — и до них нельзя дотянуться мышью. Работа оплачена, ценность не получена. |
| **3** | **Нет CI** | 1052 теста существуют, но не защищают: их надо вспомнить и запустить руками. |
| **4** | **`execution-engine.ts` 1739 строк + `index.ts` 1192 + `orchestrator.ts` 903** | Три бутылочных горлышка, где любая правка — риск. |
| **5** | **Нет предпросмотра результата** | Ключевая фича v0/Bolt/Lovable — видеть приложение, пока оно строится. У AZRAIL есть `sandbox_preview` в бэкенде, но в UI это `viewSandbox` с `<textarea>` для ручной вставки HTML. |
| **6** | **Нет потоковой выдачи в основном UI** | `/api/stream` есть, тикеты есть, но пользователь видит результат шагами опроса, а не буквами. Конкуренты стримят токены. |
| **7** | **Нет CSP, X-Frame-Options ломает превью** | Прод-безопасность и DX конфликтуют, оба проигрывают. |
| **8** | **Нет e2e и визуальных тестов** | Фронт защищён регулярками по CSS-тексту. |
| **9** | **Два entry point (`index.ts` / `index.free.ts`)** | Free-профиль никем не проверяется. |
| **10** | **Документация 108 КБ в одном `README.md`** | Никто это не читает. Есть ещё 7 MD в корне и 2 папки аудитов. |

## 3. Бенчмарк: топ-5 мировых платформ

Данные собраны из обзоров 2026 года ([Mocha](https://getmocha.com/blog/best-ai-app-builder-2026), [appbuilder24](https://appbuilder24.com/blog/bolt-vs-lovable-vs-v0-vs-base44-ai-app-builder-comparison-2026), [DigitalApplied](https://www.digitalapplied.com/blog/ai-app-builders-v0-lovable-bolt-replit-comparison), [ToolJet](https://blog.tooljet.com/lovable-vs-bolt-vs-v0/), [Replit](https://replit.com/discover/bolt-new-alternatives)).

### 3.1 Кто и чем силён

| Платформа | Ядро преимущества | Что забирать в AZRAIL |
|---|---|---|
| **v0 (Vercel)** | Лучшее в индустрии качество UI: React+Tailwind+shadcn/ui. Композитная архитектура: retrieval → frontier LLM → **AutoFix-постпроцессор**, который чинит ошибки прямо в момент генерации. Design Mode — визуальная правка. | **AutoFix-цикл** (у AZRAIL уже есть `syntax-guard` + `checker` + `reflection` — не хватает только связать их в видимый пользователю авто-ремонт) и **визуальный редактор результата**. |
| **Lovable** | Прямой путь «промпт → рабочее приложение с БД и авторизацией» за минуты. Supabase «из коробки», визуальное редактирование, встроенное сканирование безопасности. | **Один непрерывный сценарий без переключения окон.** Это ровно то, чего у AZRAIL нет. |
| **Bolt.new** | WebContainers: Node.js целиком в браузере. Итерация в секундах, ноль установки. Мультимодельность (Claude/GPT/Gemini на выбор), импорт из Figma, двусторонний GitHub sync. | **Выбор модели пользователем** (у AZRAIL есть `model-registry` с 11 провайдерами и иконками — полуготово) и **живой предпросмотр рядом с чатом**. |
| **Replit Agent 4** | Самая высокая автономность: работает до 200 минут, сам тестирует свой код, порождает субагентов, показывает каждый шаг. 30+ интеграций, БД/хостинг/деплой в одном месте. | **Показ каждого шага агента** — у AZRAIL это `trace`, но спрятан. И **самотестирование** — есть `qa-agent` + `sandbox_test`, не выведено в UI. |
| **Cursor** | Не app-builder, а IDE-агент: глубокая работа по существующему репозиторию, карта кода, точечные правки. | **Работа с чужим репозиторием как первоклассный сценарий** — у AZRAIL есть `repo-map`, `git-agent`, `zip-reader`, приём GitHub-репо. Это дифференциатор. |

## 4. План выхода в №1

### Этап A — единая оболочка (ядро работы)

Одна SPA `index.html` вместо четырёх страниц. Один дизайн-язык, один вход, одно состояние.

```
AZRAIL OS
├── Создать        ← композер + глобус + примеры (первый экран)
├── Миссия         ← живая трассировка шагов, стрим, подсказка на ходу, стоп
├── Предпросмотр   ← результат рядом, не в textarea
├── Чат            ← /api/chat, ветки, история
├── Студии         ← UI / Git / QA / Deploy / Security / Architect / Evolution
├── Лаборатории    ← Bench, Selftest, Каталог моделей, Health моделей
├── Проект         ← файлы, версии, память, история, бэкапы, метрики
└── Управление     ← аккаунты, роли, тарифы моделей, бюджет  (только admin)
```

Все 55 эндпоинтов получают интерфейс. Ни одной кнопки без поведения.

### Этап B — глобус

Медленно вращающийся глобус с орбитальными кольцами на первом экране и в свёрнутом виде в шапке как индикатор состояния (спокойный → пульсирует во время миссии).
**Жду ваш HTML-файл**, чтобы взять оттуда точную геометрию и параметры анимации, а не выдумывать своё. Требования, которые применю при интеграции:
`prefers-reduced-motion` → остановка; `requestAnimationFrame` с паузой при `document.hidden`; canvas 2D без внешних зависимостей (CSP-совместимо).

### Этап C — заимствования у топ-5

| Откуда | Что | На чём в AZRAIL строится |
|---|---|---|
| v0 | Видимый AutoFix: «нашёл ошибку → чиню → проверил» | `syntax-guard` + `checker` + `reflection` |
| Replit | Пошаговый лог агента крупным планом | `mission-trace`, `/api/stream` |
| Bolt | Переключатель модели в композере | `model-registry` + 11 иконок в `public/icons/` |
| Lovable | Один сценарий без переключения окон | Этап A |
| Cursor | Импорт репозитория/ZIP как равноправный вход | `zip-reader`, `git-agent`, `repo-map` |

### Этап D — инженерная гигиена

1. GitHub Actions: `typecheck` + `test` + `build:ui` на каждый push.
2. CSP вместо `X-Frame-Options: DENY`; вынос инлайн-JS в отдельные файлы.
3. Разбиение `index.ts` на таблицу маршрутов, `execution-engine.ts` — по фазам.
4. Playwright e2e на главный сценарий.
5. Слияние `regressions.test.ts` (3165 строк) по темам.

## 5. Что нужно от вас, чтобы начать этап A

1. **`dark-mnmll-pulse-os-cloudflare-1.0.0.zip`** — сольём его логику и модули в этот репозиторий. Без архива я не знаю, что именно там есть сверх текущего кода.

Как только файлы будут приложены — собираю единую оболочку и запускаю живой предпросмотр в этом же окне.
