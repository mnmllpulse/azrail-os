# AZRAIL OS 0.6.3 — проверенный пакет исправлений

Дата: 25 сентября 2026. Основа: предоставленный azrail-os(2).zip, версия 0.6.2.

Это исходники с исправлениями, тестами и инструкцией обновления. Это не образ уже развёрнутой системы. Cloudflare, GitHub, AI Gateway и контейнер в вашем аккаунте в этой работе не изменялись.

- `docs/audit-2026-09-25/ROADMAP_RU.md` — что делать дальше, в каком порядке и как принимать результат.
- `docs/audit-2026-09-25/VALIDATION.md` — выполненные проверки и границы их достоверности.

- `docs/audit-2026-09-25/FILES.json` — перечень изменённых и добавленных файлов с SHA-256.
- `migrations/004-security-hardening.sql` — новые таблицы защиты расходов, билетов и повторов.

## Обновление существующей установки

1. Сохраните резервную копию D1 и рабочей области R2. Зафиксируйте текущую версию Worker для возможного отката.
2. Используйте Node.js 24 и выполните `npm ci`, затем `npm run check`.
3. Проверьте `wrangler.toml`: исходные ID D1/KV и имя R2 сохранены. Для другого аккаунта нужны его собственные ресурсы. Секреты хранятся в Cloudflare, не в ZIP.
4. Примените **сначала миграцию**, затем выкладывайте код:
   ```sh
   npm run db:security
   ```
   Это команда для удалённой D1. Она добавляет таблицы/индексы, не удаляет существующие данные. Её можно повторять. Предполагается, что исходная схема 0.6.2 уже применена.
5. Выполните `npm run build:check`. Это только проверка Worker, без сборки контейнера и без публикации.
6. На машине с Docker выполните `npm run deploy`. Эта команда публикует Worker и собирает контейнер. SDK Sandbox закреплён на 0.12.9, как Dockerfile.
7. Проверьте: вход по токену; `/health` с Authorization; загрузку ZIP; сообщение в чате; запуск миссии; повтор с тем же Idempotency-Key; отмену; WebSocket; чтение результата.

Для новой базы сначала примените `schema.sql` штатной командой `npm run db:schema`. Не применяйте все исторические SQL подряд к свежей схеме: старые ALTER TABLE могут добавлять уже существующие колонки. Для старой установки проверьте, что миграции 002 и 003 были выполнены ранее.

## Изменения совместимости

- Постоянный токен в `?token=` больше не принимается. Используйте `Authorization: Bearer ...`; браузерный WebSocket получает билет через `/api/stream/ticket`.
- `/agents/*` закрыт. Используйте прикладные API и `/api/stream`.
- `/health` требует токен: обновите настройки монитора доступности.
- Если новые таблицы D1 не созданы или D1 недоступна, защищённые платные операции отказывают. Это намеренное закрытие доступа при невозможности учёта.
- Подтверждённый повтор миссии возвращает исходный ответ 202 и `Idempotency-Replayed: true` без повторного списания. Пока первый запрос не закончен — 409 `idempotency_pending`; с другим телом — 409 `idempotency_conflict`.
- Ключ повторов действует 24 часа и сравнивает точные байты JSON. Клиент должен повторять то же тело с тем же ключом. После неоднозначного 5xx ключ сохраняется: сначала проверьте миссии, не создавайте новый ключ автоматически.
- На проект допускается одна активная миссия через `/api/mission`. Другие изменения через Git/task пока не охвачены общей блокировкой.
- Квоты отражают условные единицы запуска, а не точную сумму счёта. Отказ после резервирования может израсходовать квоту без вызова модели.
- Чтение JSON ограничено 1 МиБ фактически полученных байтов. Загрузка файла — 50 МиБ плюс 1 МиБ multipart-оболочки.

Не откатывайте код на старую версию без необходимости: это вернёт исправленные обходы защиты. Добавленные таблицы совместимы с сохранением старых данных, удалять их для отката не требуется.
