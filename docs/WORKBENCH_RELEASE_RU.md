# AZRAIL Workbench 1.5.0-rc.1

Первичная проверка: 4 октября 2026 года. Обновление staging: 9 октября 2026 года. Первый этап: ядро, плагины и создание приложений.

Кандидат выпуска опубликован в отдельном staging: https://azrail-pulse-staging.mnmllpulse.workers.dev. Вход владельца через OIDC подтверждён. Оплачиваемые запросы OpenAI, внешний OAuth, исполнение контейнеров и полный сценарий приёмки ещё требуют отдельной проверки. Актуальные результаты: [STAGING_STATUS_RU.md](STAGING_STATUS_RU.md); 1307 тестов, TypeScript и сборка UI успешны. Название модели в каталоге не является доказательством оплаченного доступа к ней.

## Исправленные ошибки

1. Завершившееся чтение вложения больше не переносит текст в другой проект; аналогично проверяется результат голосового ввода.
2. Сохранение сгенерированного изображения использует PATCH существующего артефакта.
3. Студийные черновики и результаты не смешиваются между проектами.
4. Устаревшее окно редактора не перезаписывает более свежие файлы молча.
5. Подтверждённый отказ при выборе модели освобождает admission-ключ вместо вечного состояния «в работе».
6. Ошибка остановки предпросмотра сохраняет запись для повторной очистки; истёкший адрес уже недоступен.
7. `html_handling: none` убирает обнаруженную в реальном локальном Cloudflare runtime петлю перенаправлений `/app.html` → `/app`.
8. Алиасы `/api/azrail/*` проходят ту же авторизацию и защиту от повторного запуска, что канонические API.

## Первичная локальная проверка, 4 октября

- `npm run check`: сборка интерфейса, обе проверки TypeScript, 1284 теста в 66 файлах.
- Сборки Workers Free и Paid: Wrangler dry-run завершён успешно; это не проверка удалённого контейнера.
- Проверены ограничения владельца, viewer, CSRF, CAS, квоты, повторные и неопределённые операции, OAuth refresh, восстановление версий и миграции.
- Chromium + локальный Wrangler/D1/R2: создан проект, записан HTML-файл, показан изолированный предпросмотр; сохранены разрешения плагинов, лимит задачи и версия. Проверены восстановление, мобильная ширина 390 px и отсутствие JavaScript-ошибок в этом сценарии.
- В браузере использована искусственная сессия только для localhost. Производственный OIDC не подменялся и не проверялся.
- Платные модельные ответы и внешние OAuth-сервисы проверялись моками. Реальных платных API-вызовов не выполнялось.

## Как открыть и запустить

Для просмотра интерфейса без сервера откройте корневой `index.html`. Локальные творческие студии доступны, но серверные проекты и модели требуют развёрнутого приложения.

Для разработки нужен Node.js 24+:

```sh
npm ci
npm run check
```

Для Cloudflare используйте Unified-конфигурации `wrangler.json` / `wrangler.paid.json` и инструкции `DEPLOY_RU.md`. Унаследованные `wrangler.toml`, старые экраны Pulse/Globe и документы прошлых версий сохранены для истории; активный Workbench ими не запускается. Для отдельного тестового окружения см. `docs/STAGING_RU.md`.

Перед выкладкой нужно выбрать целевой Worker и ресурсы явно: в подключённом аккаунте обнаружен `azrail-os`, а шаблоны ZIP используют `azrail-pulse`. Нельзя считать их одним окружением. Рабочая ветка опубликована: `codex/azrail-workbench-staging-20261008`, [PR #12](https://github.com/mnmllpulse/azrail-os/pull/12).

Дальнейшая настройка:

1. OIDC issuer/client, публичный origin, стабильный ключ хранилища подключений; секреты только на сервере.
2. Резервная копия D1, проверка плана миграции, миграция 010–013 и проверка существующих данных.
3. Для OpenAI — серверный `OPENAI_API_KEY`, включённая политика платных моделей, месячный бюджет и актуальные цены в `model_prices`. Цена без повторной проверки действует максимум 7 дней. Создание ключа производится отдельно через безопасный выбор проекта OpenAI Platform.
4. Для работающего preview — Paid Sandbox binding, права проекта и отдельный `SANDBOX_PREVIEW_HOSTNAME` с wildcard DNS. Preview действует 10 минут; код пользователя не получает cookie/Authorization приложения.
5. Для GitHub, Canva и прочих сервисов — операторский MCP allowlist, OAuth-клиент сервиса, пользовательское подключение, проверка инструментов и выдача прав проекту. Подключённые к этой беседе плагины не становятся автоматически подключениями внутри AZRAIL.
6. Контрольный сценарий в staging с реальными OIDC и провайдерами; только затем производственный выпуск.

Старые поля `preferredMode` и `preferredStudio` отклоняются с явным кодом `routing_profile_deprecated`; используйте настройки модели проекта. Старый PATCH проекта заменён обновлением с `baseRevision`.

## Практические ограничения RC1

- Статический preview не исполняет React/TypeScript. Для работающего приложения нужна установленная и разрешённая песочница; файлы, изменённые произвольной runtime-командой, автоматически обратно не публикуются.
- Редактор ограничен 400 файлами / 16 МиБ на проект и 1 МиБ на текстовый файл. Полные снимки занимают дополнительное R2; единая квота всех рабочих файлов/версий аккаунта ещё не реализована.
- Квота артефактов студий по умолчанию: 128 МиБ / 1000 файлов на аккаунт. Неопределённая запись удерживает квоту до сверки; автоматическое освобождение по таймеру запрещено.
- OpenAI-адаптер в RC1 принимает текст, функции и структурированный ответ; запрос ограничен 200 000 байт, вывод — 32 768 токенами. Потоковая выдача токенов, прямой мультимодальный ввод и встроенные инструменты Responses пока не подключены.
- Каталог не устанавливает произвольные npm-пакеты или сторонний исполняемый код. Пользовательские skill-пакеты, подписи, магазин и политика обновлений — следующий этап.
- Восстановление последней активной миссии в UI пока опирается на состояние вкладки аккаунта/проекта; возобновление с другого устройства требует дополнительного серверного списка последних миссий.
- Нельзя утверждать равенство GPT/Claude по качеству на основании списка кнопок. Нужны сравнительные задания с замером успешности, времени, стоимости и числа ручных исправлений.
