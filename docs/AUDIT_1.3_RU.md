# Аудит AZRAIL × MNMLL PULSE OS — Unified 1.3.0

Проверка от 30 сентября 2026. В ZIP внесены изменения задания из PDF, а не только архитектурные рекомендации. Основной список функций и оставшихся работ: [TASK_1.3_RU.md](TASK_1.3_RU.md).

## Исправленные ошибки и слабые места

1. Интерфейс миссии показывал технические структуры без ясного хода работы. Добавлены план, резюме и реальные статусы; JSON доступен отдельно.
2. Повторный просмотр после обрыва сети не имел понятного состояния. Добавлено восстановление GET без повторного старта миссии.
3. Студийные поля теряли историю и состояние. Добавлены Undo/Redo/Reset, D1-черновики и optimistic revision; конфликт не скрывается.
4. Ошибка студии могла оставлять надпись «Выполняю…». Теперь рабочая область показывает ошибку, сохраняя параметры.
5. Повтор image POST после потери ответа создавал новый UI idempotency key. Теперь сохраняются точные тело и ключ, а редактирование неопределённого запроса блокируется до проверки.
6. Внешние плагины существовали преимущественно как план. Добавлен серверный MCP transport, tool discovery, ограниченный поиск, вызов и история операций.
7. Удалённая аннотация readOnly могла быть ошибочно принята за право. Риск определяется серверной политикой; все прочие инструменты требуют точного подтверждения.
8. Двойное подтверждение могло дать двойной внешний эффект. D1 CAS допускает одного исполнителя; повтор возвращает сохранённый результат.
9. После потери ответа нельзя отличить невыполнение от выполненного действия. Состояние uncertain удерживает резерв и запрещает автоматический повтор.
10. Ошибка Ledger после сохранённого ответа могла скрывать успех. Ответ теперь остаётся доступным; следующий replay завершает settlement без нового tools/call.
11. Проверка лимита подключений только до INSERT допускала гонку. Лимит проверяется в атомарном INSERT; OAuth state также ограничен.
12. Новые переменные не проходили через GitHub pipeline. Добавлены MCP_SERVERS, INTEGRATION_KEY, MCP_OAUTH_SECRETS и проверки миграции 009.
13. Типографика и другие токены генерации не сохранялись в проекте. Добавлен DesignContract с ownership, CAS и проверкой контраста.
14. Аудиоанализ учитывал только первый канал и не имел спектра. Теперь уровни учитывают оба канала, FFT суммирует мощности без взаимного погашения противофазы; доступно сравнение с референсом.
15. Формы MCP не корректно обрабатывали необязательные и сложные schema-поля. Добавлены пропуск необязательных значений и явный JSON-редактор; сервер остаётся окончательной границей JSON Schema validation.

## Проверки

- `npm run check`: сборка HTML/assets, TypeScript, **54 набора / 1132 теста — пройдены**.
- Free Worker dry-run — пройден.
- Paid Worker dry-run — пройден; это не запуск и не проверка Docker-контейнера.
- `npm audit`: **0 известных уязвимостей** в установленном дереве зависимостей на момент проверки.
- OAuth: replay, expiry, чужой аккаунт, смена политики, PKCE/resource, шифрование, malformed token response и лимиты.
- Connector: JSON/SSE, schema validation, двойное подтверждение, потеря ответа, квота, disconnect, stale catalog, запрет самоподтверждения агентом.
- DesignContract: ownership, конкурентная запись, revision, контраст, обязательные UI-состояния.
- Аудио: синус с известной RMS/частотой, противофаза, правый канал, тишина, gain comparison и отмена.

D1 проверялся реальным SQLite через тестовый адаптер. Cloudflare runtime и удалённые провайдеры в тестах имитируются. Старые наборы также содержат статические проверки. Суммарное число тестов не равно числу пользовательских сценариев, проверенных в production.

Точный результат попытки запуска браузера записан в `docs/verification/v1.3/browser.txt`. DOM-тесты не подтверждают реальный GPU/WebGL и мобильный рендер. Live E2E, deploy на домены и интеграции аккаунтов в этой поставке не выполнены.

## Границы готовности

Архив пригоден для review, локальной сборки и последующего настроенного развёртывания. Полная публичная SaaS-приёмка ещё не завершена. Главные блокеры: live OIDC/Workers AI/MCP, мобильная проверка, Sandbox, backup restore, финансовая сверка и отсутствующие специализированные студии/адаптеры. Подробности и критерии завершения находятся в [TASK_1.3_RU.md](TASK_1.3_RU.md).
