# Архитектура AZRAIL OS Ultimate

## Продуктовый контракт

Пользователь описывает желаемый результат одним запросом. AZRAIL определяет необходимый контекст, составляет исполнимый план, создаёт артефакты, проверяет их и возвращает результат с коротким объяснением. Настройки среды подбираются автоматически в пределах заранее выданных полномочий и бюджета.

Универсальность означает возможность подключить новый тип задачи через общий контракт. Она не означает бесконечные вычисления, отсутствие доступа у внешних сервисов или автоматическое разрешение платных действий. Для неизвестного инструмента система предлагает доступный способ продолжения и не изображает его успешный запуск.

Основной пользователь первого выпуска — владелец AZRAIL. Образ «понятно ребёнку» задаёт простоту интерфейса: за шесть секунд виден следующий шаг, за минуту понятен основной цикл. Специальный детский продукт этим не заявляется.

## Слои системы

| Слой | Ответственность | Технологический выбор |
|---|---|---|
| Интерфейс | Запрос, голос, файлы, просмотр результата | Адаптивный web/PWA, простой старт, прогрессивное раскрытие |
| Доступ и политика | Личность, права проекта, стоимость, разрешения | Worker API, серверный Policy Engine, журнал решений |
| Управление миссией | План, зависимости, запуск, восстановление | Durable Object на проект, D1, outbox; затем долговечные workflows |
| Исполнители | Код, дизайн, данные, исследования, мультимедиа | Роли с ограниченным набором инструментов |
| Модели | Допуск, подбор, тариф, запасной маршрут | Workers AI и отдельный разрешённый Gateway-маршрут |
| Песочница | Команды, файлы, preview, тесты | Интерфейс SandboxProvider; Cloudflare первым, альтернативы по профилю |
| Интеграции | OAuth, REST, MCP, секреты, ограничения | Connector Gateway и реестр адаптеров |
| Артефакты и память | Файлы, версии, решения, источники | R2 для объектов, D1 для метаданных, поисковый индекс по необходимости |
| Контроль качества | Проверка сценария и доказательства | Сборка, тесты, браузер, доступность, безопасность, ручная приёмка |

Секреты и платёжная политика не входят в промпт как редактируемая пользователем строка. Модель получает только эффективные разрешения и доступный набор инструментов. Сервер повторно проверяет каждый вызов.

## Команда агентов

Сохраняются существующие девять ролей. Оркестратор получает исполнимый граф работы, а не просто длинный список размышлений. Research Agent собирает источники; Product Agent формирует сценарии и критерии; Design Director поддерживает визуальный контракт; Audio Agent управляет музыкальной работой; Connector Agent подготавливает подключения; Reliability Agent проверяет восстановление. Роль может быть обычным модулем и не обязана постоянно запускать отдельную дорогую модель.

Параллельно выполняются независимые чтения, анализ разных материалов и подготовка отдельных артефактов. Изменение одних и тех же файлов, схемы данных или активного релиза сериализуется. Результаты дочерних задач принимаются по контракту, а не по фразе агента «готово».

Для Free по умолчанию один активный исполнитель и короткий контекст. Для Hybrid допускается ограниченная параллельность после резервирования общей стоимости. Число агентов выбирается по ускорению критического пути; нельзя создавать команду ради количества.

## Контракты выполнения

MissionSpec содержит missionId, projectId, ownerId, goal, inputArtifacts, acceptanceCriteria, dependencies, policyRevision, modelMode, budgetReservation, deadline, cancellationState и checkpoints. Все идентификаторы и полномочия проставляет сервер. Текст запроса не может назначить себе ownerId или изменить режим оплаты.

ToolCall содержит уникальный callId, тип действия, схему аргументов, список необходимых прав, idempotencyKey и контекст ресурса. ToolResult возвращает status, artifactRefs, evidenceRefs, usage, retryDisposition и errorCode. Ошибки делятся на повторяемые, требующие уточнения и имеющие неопределённый внешний эффект.

Artifact содержит MIME-тип, размер, SHA-256, версию, происхождение, область доступа и место хранения. EvidenceReceipt содержит проверку, команду или сценарий, время, версию артефакта, результат и журнал. Ссылка на прошлую успешную сборку не подтверждает новый изменённый файл.

ConnectorManifest содержит id, version, transport, authType, scopes, actions, riskClass, priceUnits, webhookVerification, healthCheck и dataRetention. При отсутствии нужного действия подключение отображается как частичное. Имена сервисов в каталоге не приравниваются к установленным адаптерам.

## Состояния миссии

Основной цикл: accepted → planning → ready → running → validating → completed. Дополнительные состояния: waiting_input, waiting_access, waiting_budget, paused, cancelling, cancelled, failed и uncertain_effect.

Состояние uncertain_effect означает, что внешний сервис мог принять действие, но подтверждение потеряно. Автоматический повтор платежа, публикации или создания объекта запрещён до сверки. Отмена закрывает новые шаги; уже начатые шаги завершаются или прерываются только при поддержке адаптером. Пользователь видит эту границу.

Перед изменением рабочей версии записывается checkpoint. Новая версия публикуется атомарной сменой указателя после проверки. Для восстановления блокировки добавляется возрастающий fencing token: старый исполнитель не может записать данные после передачи проекта новому.

## Бесплатный профиль и сторонние модели

Workers AI предоставляет дневную бесплатную квоту 10 000 neurons. Это вычислительная единица, не 10 000 запросов и не 10 000 токенов. На Workers Free исчерпание квоты прекращает доступ; Workers Paid позволяет тарифицируемое превышение. Некоторые hosted-модели отдельно требуют Paid. Контейнерный Sandbox также требует Paid. [S20–S24]

Скриншот пользователя подтверждает отображение 229 моделей в его каталоге на момент снимка. Он не подтверждает, что все 229 являются сторонними или доступны бесплатно. В проверенном ответе Workers AI Search получено 65 записей; метаданные total_count показывали 313 и не совпадали с возвращённым набором. Эти разные счётчики нельзя складывать или выдавать за одну точную величину. В интерфейсе AZRAIL показывается источник, время и фактический размер полученного ответа.

В 0.8 Free-допуск сознательно ограничен шестью проверенными текстовыми и embedding-моделями. Это не весь каталог Cloudflare: Qwen Coder для файлов кода, Llama для текста и инструментальных решений, Qwen3 и GPT-OSS для рассуждений, BGE для поиска. Whisper и FLUX предусмотрены для следующих специализированных адаптеров с собственными единицами учёта.

OFF — исходное состояние D1. Разрешены только модели проверенного Free-списка прямым binding, без Gateway. Платный hosted-вариант, сторонний endpoint, ручной выбор модели и запасной маршрут подчиняются одному запрету. Ошибка чтения политики оставляет платные маршруты закрытыми. Клиентская кнопка сама по себе не является защитой.

ON — явное действие владельца. Для платного вызова нужны настроенный Gateway, свежий тариф, положительный месячный бюджет и атомарная резервация. Возврат OFF не обнуляет расходы. Телефон и компьютер используют одну серверную настройку; устройство не включает платный режим автоматически.

Текущий код считает платные текстовые вызовы и удерживает резерв при неизвестном usage. До общего запуска требуется расширить счётчик на reasoning, кеш, разные классы контекста, изображения, аудио, инструменты и инфраструктуру. Смета не может быть нулевой, если цена неизвестна. До точного адаптера сложного тарифа модель остаётся недопущенной к соответствующему режиму.

Unified Billing в проверенной документации описан как покупка кредитов заранее, с комиссией покупки 5%. Отрицательный остаток в отдельных случаях может попасть в следующий счёт. Это не обещание всем аккаунтам оплачивать любые модели в кредит в конце месяца. Workers Paid от $5 — отдельная плата. Gateway spend limits применяются и к BYOK, но имеют eventual consistency и могут пропустить кратковременное превышение при параллельных запросах. Поэтому локальный резерв нужен дополнительно. [S25–S27]

Публичная документация OpenAI подтверждает GPT-6 Astra и окно 1 050 000 токенов. Это не подтверждает тариф и доступность именно через Gateway конкретного аккаунта. Для Astra и указанной пользователем Fable 5.1 нужен точный provider ID, схема запроса, разрешённый путь оплаты и контрольный вызов после активации владельцем. Названия не подменяются выдуманными ID. [S28]

## Пять сред исполнения

| Среда | Документированная сильная сторона | Что заимствуем | Ограничение выбора |
|---|---|---|---|
| Cloudflare Sandbox | Команды, файлы, фоновые процессы и preview рядом с Workers | Первый облачный адаптер и единая идентификация проекта | Требует Workers Paid; лимиты контейнеров учитывать отдельно |
| E2B | Сохранение и продолжение среды, включая память в поддерживаемом режиме | Контракт suspend/resume и явное описание, что сохраняется | Доступность и стоимость режима зависят от продукта |
| Daytona | Жизненный цикл sandbox, снимки, предварительные среды | Шаблоны и управление TTL для длительных задач | Снимок VM с памятью отличается от файлового снимка контейнера |
| Vercel Sandbox | Изолированные microVM, сетевые политики, снимки | Доступ к сети по разрешённым адресам и выдача секретов посредником | Другой облачный провайдер, отдельный бюджет |
| GitHub Codespaces | devcontainer, prebuilds, порты и секреты разработки | Воспроизводимая среда и передача проекта человеку | Среда разработчика не становится автоматически backend для всех агентов |

Источники: S24, S29–S34. Сравнение возможностей не доказывает, что одна система быстрее остальных на нагрузке AZRAIL.

## Десять функций будущей песочницы

| № | Функция и основание | Реализация AZRAIL | Критерий готовности |
|---|---|---|---|
| 1 | Изоляция исполнения по примеру microVM | SandboxProvider и область project/mission | Одна миссия не читает файлы и секреты другой |
| 2 | Pause и resume по примеру E2B | Снимок состояния и декларация memory/filesystem | После паузы сохраняются именно заявленные ресурсы |
| 3 | Снимок перед изменением по примеру Daytona и Vercel | Версии, checkpoint, ветвление | Восстановление возвращает проверенный SHA-256 |
| 4 | devcontainer по примеру Codespaces | Версионируемый образ и lockfile | Повторная сборка получает тот же набор зависимостей |
| 5 | Prebuild и тёплая среда | Кеш по digest образа и lockfile | Измеряется p95 холодного и повторного старта |
| 6 | Preview с управлением доступом | Короткая ссылка с областью проекта и сроком | Чужой пользователь получает отказ, старый токен истекает |
| 7 | Поток команд и фоновые процессы | PTY, stdout/stderr, exit code, process registry | Есть полный журнал и подтверждённая остановка процесса |
| 8 | Сетевая политика и посредник секретов | Запрет по умолчанию, разрешённые домены | Тест блокирует неизвестный адрес и вывод ключа |
| 9 | Жизненный цикл и стоимость | TTL, auto-stop, CPU/RAM/disk/time quotas | Зависшая команда не остаётся работать бесконечно |
| 10 | Браузерная проверка результата | Сценарии, снимки, доступность, сохранение evidence | Проверяется целевой путь пользователя, а не только сборка |

Бесплатное облачное ядро не получает контейнер за счёт переименования модуля. Для Free предлагается браузерный preview статических файлов и экспорт кода. Локальный runner на ПК — отдельный будущий адаптер; у него будут pairing, ограниченная рабочая папка, сетевые правила и возможность отключения. Включать произвольный shell на телефоне невозможно.

## Генерация премиального продукта

Простой запрос разворачивается в Product Brief: аудитория, цель, основные сценарии, данные, критерии завершения и визуальный характер. Из контекста можно выбрать разумные значения по умолчанию. Если различие меняет бизнес-модель, данные или стоимость, задаётся один конкретный вопрос с вариантами.

Затем создаётся Design Contract: типографика, токены, компоненты, иерархия, плотность, адаптивность, состояния ошибок, пустые состояния и требования доступности. Генерация опирается на компоненты и дизайн-контракт. После реализации выполняются сборка, функциональный сценарий, визуальный анализ и проверка доступа к данным.

Цена SaaS «от $10 000» — ориентир коммерческого уровня результата, а не свойство модели. В состав приёмки входят рабочий вход, роли, данные, платежи в тестовом режиме, обработка webhook, восстановление, мониторинг и инструкция владельцу. Без этого красивый landing page не считается готовой SaaS-платформой.

## Визуальный и голосовой модули

Графический модуль получает тип изображения, размер, стиль, назначение, референсы, ограничения бренда и разрешения на материалы. Он выдаёт версии файлов, метаданные генерации и варианты. Точная диаграмма, таблица и UI-компонент строятся структурным инструментом, а не случайной растровой генерацией. Рабочий endpoint каждого media-провайдера проверяется отдельно.

Голосовой модуль: нажатие микрофона → запись с видимым индикатором → Whisper через разрешённый hosted-адаптер → редактируемая расшифровка → обычная миссия. Поддерживаются команды «стоп», «продолжи» и уточнения. Публикация или платное усиление не разрешаются случайной фразой в фоне. Для недоступного микрофона остаётся текстовый ввод. В 0.8 запись и транскрипция ещё не реализованы.

## Визуальный язык интерфейса

Главный экран: знак AZRAIL, один ввод, одна основная кнопка, прикрепление, голос и четыре коротких примера. Статус стоимости расположен рядом, но не конкурирует с задачей. Результат показывает состояние, созданные файлы и предпросмотр. Технические логи доступны по раскрытию.

Токены: фон #09080F, поверхность #13101D, акцент #B497F4, текст #F5F2FB, вторичный текст #AAA1B8. Шрифт системный для быстрого открытия; сетка кратна 4 px. Интерактивная область от 44 px; фокус видим, движение учитывает prefers-reduced-motion. Цвет не является единственным способом сообщить состояние.

Раздел «Студии» показывает все направления с обозначением готовности; «Управление» содержит роли и восстановление. Не добавляются отдельные кнопки под каждую модель и агента. Мобильный интерфейс сохраняет основной сценарий, а не пытается уместить весь IDE.

Готовый концепт Canva: https://canva.link/kpgm073lj55uv7v. Код нового экрана находится в public/ultimate.html, ultimate.css и ultimate.js. Это интерфейс к существующей API; отсутствие подключённого сервера и мультимедийных адаптеров показано явно.
