# Аудит AZRAIL OS и сравнение систем

Дата проверки: 25 сентября 2026 года. Версия пакета: 0.8.0. Назначение: определить, что уже реализовано, какие ограничения мешают универсальности и какие решения перенести в следующую архитектуру.

AZRAIL имеет рабочую основу для агентной разработки: оркестратор, специализированные исполнители, файловые инструменты, управление миссиями, Git и проверку кода. Следующий качественный скачок требует законченных пользовательских сценариев, изолированной среды исполнения и единого контроля ресурсов. Количество моделей само по себе не закрывает эти задачи.

Цель «номер один» принимается как направление развития. Фактическое превосходство устанавливается сравнительными испытаниями на одинаковых задачах и бюджетах. В этом пакете нет заявления, что такие испытания уже выиграны. «Делает всё» означает расширяемые классы задач и настойчивое выполнение доступным способом, с понятным продолжением при нехватке доступа или ресурсов.

## Основание аудита

Проверены исходники предоставленного AZRAIL, миграции D1, реестр моделей и инструментов, маршрутизатор, движок миссий, обработчики HTTP, пользовательские страницы и тесты. Дополнительно найден доступный репозиторий mnmllpulse/azrail-os: на момент чтения package.json в main содержит версию 0.6.2. Изменения этого пакета в GitHub не отправлялись. ZIP является самостоятельным комплектом для проверки и переноса изменений.

Конкуренты исследованы по публичной официальной документации. Закрытые алгоритмы маршрутизации, качество на неизвестных задачах и внутренняя организация команд не считаются установленными. Эстетические выводы ниже являются проектной оценкой интерфейсных подходов, а не результатом лабораторного UX-исследования.

## Что уже есть в AZRAIL

| Область | Подтверждено в исходниках | Практическая граница |
|---|---|---|
| Команда | Answer, Architect, Code, UI, Git, Deploy, Security, QA, Evolution | Девять ролей не означают девять независимых универсальных автономных систем |
| Оркестрация | Определение намерения, выбор исполнителя, цикл миссии, проверки и история | Полного планировщика зависимостей между мультимодальными задачами пока нет |
| Файлы и код | Чтение, поиск, запись, исправление, патчи, генерация файлов | Результат необходимо проверять сборкой и исполнением |
| Выполнение | Cloudflare Sandbox и ограниченный путь GitHub Actions | Контейнер требует Workers Paid; Actions имеет свои квоты и доступы |
| Состояние | D1, KV, R2, outbox, контрольные точки, восстановление | Не подтверждена сквозная надёжность после всех видов аварий |
| Доступ | Ключи аккаунтов, роли, владение ресурсами, разрешения проекта | Для публичного SaaS нужны OIDC и полноценная изоляция арендаторов |
| Копии | SHA-256, копия файлов, восстановление в новый проект | Копия файлов не заменяет полный бэкап D1 и интеграционных настроек |
| Модели | Реестр, маршрутизация, запасные модели, журнал попыток | Не все модели кабинета имеют проверенный адаптер AZRAIL |
| Новое в 0.8 | Серверный OFF/ON, месячный резерв платных вызовов, чтение живого каталога | Это не общий финансовый лимит всех сервисов Cloudflare |
| Мультимедиа | Спецификация студий и маршрутов | Голос, изображения, видео, музыкальный рендер и Beatport ещё не подключены |

## Слабые места и исправления

| Приоритет | Находка | Последствие | Решение и состояние |
|---|---|---|---|
| P0 | Наличие AI Gateway раньше позволяло платный маршрут без отдельного переключателя | Непредвиденный платный вызов | Исправлено: серверный режим по умолчанию OFF, проверка перед каждой попыткой |
| P0 | Префикс @cf ошибочно можно принять за признак бесплатности | Выбор модели, требующей Paid | Исправлено: отдельный проверенный список допуска Free |
| P0 | Hosted-модели передавались через Gateway при наличии его ID | Возможное использование другого биллингового пути | Исправлено: модели Free-списка вызываются прямым AI binding |
| P0 | Параллельные платные задачи могут одновременно израсходовать остаток | Превышение локального бюджета | Добавлено атомарное резервирование общей месячной области D1 |
| P0 | Отмена миссии действует между шагами | Отправленный запрос может завершиться и тарифицироваться | Оставлено честное сообщение; сквозной AbortSignal и статус in-flight входят в этап надёжности |
| P0 | Нет полного ограничения исходящей сети контейнера | Код может обращаться к лишним ресурсам | Обязательное условие публичного запуска: изоляция сети и выдача секретов через посредник |
| P0 | Нет fencing token у блокировки проекта | Сложное восстановление после падения старого исполнителя | Добавить номер эпохи, проверку перед каждой записью, процедуру безопасной передачи владения |
| P1 | Реестр инструмента может быть воспринят как готовая функция | Пользователь ожидает работающую музыку или браузер | Новый интерфейс различает реализованные и запланированные студии |
| P1 | Генератор кода требовал native tool calling, хотя возвращает файлы текстом | Qwen Coder исключался без необходимости | Исправлено требование маршрута generate_code; проверка формата файлов сохраняется |
| P1 | Каталог интерфейса показывал доступность только по Gateway | Можно выбрать модель, запрещённую политикой | Исправлено: используется та же функция допуска, что на сервере |
| P1 | Тестовый набор в значительной части проверяет строки исходников | Зелёный результат не доказывает пользовательский сценарий | Добавлены поведенческие проверки политики; далее нужны live E2E и fault injection |
| P1 | Нет единой сметы модели, контейнера, хранения и внешнего инструмента | Стоимость проекта неполна | Проектируется общий Resource Ledger и подтверждение сметы |
| P1 | Тарифы и каталог меняются | Устаревший маршрут или неверная цена | Живой каталог для наблюдения; платная цена старше семи дней блокирует вызов |
| P1 | Проверяющий зависит от суждения модели | Убедительный текст может скрывать сломанное приложение | Детерминированные тесты, браузерные сценарии и независимый набор критериев |
| P2 | Много служебных элементов конкурируют с главным действием | Высокий порог входа | Добавлен отдельный простой экран /ultimate.html; служебные функции доступны глубже |

Также исправлен дефект контроля качества: исключение пользовательского валидатора ответа больше не превращается в успешную проверку. Ошибка остаётся видимой и останавливает выдачу непроверенного результата; поведение закреплено отдельным тестом.

## Пять ориентиров для продукта

Выбраны v0, Lovable, Bolt, Replit Agent и Cursor. Это пять сильных представителей разных подходов: дизайн и веб-генерация, создание приложений без настройки среды, браузерная разработка, облачная автономность и работа с существующим кодом. Список не является независимым глобальным рейтингом.

### v0

Документированы создание интерфейса по запросу, работа с Figma и дизайн-системами, визуальное редактирование элементов, терминальные команды, интеграции данных и Git. Визуальная правка связывает выбранный элемент с изменением исходников. Документация Design Mode указывает ограничение для мобильных устройств. [S01–S04]

Перенос в AZRAIL: Design Contract с токенами, компонентами, состояниями и сеткой; связка выделенного элемента с исходным файлом; импорт Figma с сохранением смысла компонентов; общая проверка кода и изображения. Для телефона нужен собственный режим выбора элемента, а не уменьшенная настольная панель. Критерий: фраза «сделай эту карточку компактнее» изменяет один компонент и сохраняет адаптивность остальных экранов.

### Lovable

Публичная модель работы включает Chat, Plan и Build, наблюдаемые изменения и инструменты тестирования. Каталог разделяет личные подключения для контекста, подключения приложения и подключения каждого конечного пользователя. Это полезное различие для предотвращения передачи личного доступа опубликованному приложению. [S05–S07]

Перенос в AZRAIL: один запрос создаёт план и артефакты; дополнительный вопрос появляется только при существенной неопределённости. У каждого подключения явно указано, чьими полномочиями выполняется действие. Критерий: личный Google Drive владельца никогда не становится общим ключом созданного SaaS.

### Bolt

Документированы быстрый старт веб-проекта, редактор и предпросмотр, история версий, работа с GitHub и встроенными сервисами. Основная поддержка ориентирована на JavaScript/Node; мобильные браузеры поддерживаются не полностью. Возврат версии кода не является восстановлением базы данных. [S08–S11]

Перенос в AZRAIL: мгновенный цикл «изменение → предпросмотр», воспроизводимая среда и раздельные точки восстановления кода и данных. Критерий: откат интерфейса не откатывает платежи и реальные пользовательские записи; восстановление данных запускается как отдельная операция.

### Replit Agent

Agent объединяет планирование, сборку, тестирование и публикацию. Документация описывает режимы мощности, проверку приложения браузером, контрольные точки, работу с разными типами артефактов и дополнительные возможности ввода. Выбор режима и подключений влияет на фактическую доступность. [S12–S15]

Перенос в AZRAIL: фоновая миссия переживает закрытие телефона; результат включает приложение и доказательства проверки; пользователь может уточнить цель во время работы. Платное усиление становится явным режимом владельца. Критерий: разрыв мобильной сети не создаёт повторный оплачиваемый запуск.

### Cursor

Публичные инструменты включают работу с кодом, терминалом, поиском, браузером и MCP. Есть настройки разрешений, проектные правила и варианты исполнения агента. Внутренние эвристики выбора действий полностью не раскрыты. [S16–S19]

Перенос в AZRAIL: понимание существующего репозитория, узкие патчи вместо постоянной регенерации проекта, правила проекта и адресный контекст. Отдельные рабочие ветки нужны для независимых задач. Критерий: небольшое изменение затрагивает необходимые файлы и проходит регрессионный сценарий без переписывания приложения.

## Сравнение по одинаковым признакам

| Система | Инструменты и код | Наблюдаемое управление работой | Подключения | UI и команды |
|---|---|---|---|---|
| v0 | UI, терминал, проверка, preview | Запрос, генерация, визуальная правка | Figma, Git, данные | Чат, Design Mode, выбор элемента |
| Lovable | Приложение, изменения, тестирование | Chat, Plan, Build | Каталог, REST, MCP | Запрос и контекст, план, результат |
| Bolt | Веб-среда, код, запуск, история | Изменение и быстрый предпросмотр | GitHub и сервисы приложения | Чат, Code view, визуальная правка |
| Replit Agent | Облачная среда, браузерные тесты | План, длительное выполнение, checkpoint | Коннекторы, MCP | Чат, мощность, управление задачей |
| Cursor | Репозиторий, терминал, браузер | Агент с правилами и разрешениями | MCP, инструменты разработки | IDE, команды, diff, контекст файлов |
| AZRAIL 0.8 | Файлы, агенты, миссии, адаптер Sandbox | Намерение, последовательный цикл, проверки | Cloudflare, GitHub; остальные в плане | Новый простой экран и полная панель |

Команды будущего AZRAIL формулируются словами: «создай», «исправь», «сравни», «покажи результат», «продолжи», «верни прошлую версию», «останови». Slash-команды и терминал остаются необязательными способами для опытного пользователя. Точная команда интерфейса конкурента не копируется ради внешнего сходства.

## Вывод для архитектуры

Главная комбинация для AZRAIL: качество интерфейсов v0, понятность продуктового сценария Lovable, короткий цикл предпросмотра Bolt, устойчивость длительных миссий Replit и точность работы с репозиторием Cursor. Это проектная цель. Соответствие каждому сценарию фиксируется отдельным тестом и измерением, а не отметкой «поддерживаются все модели».
