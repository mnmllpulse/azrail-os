# AZRAIL OS · пошаговый разбор, слабые места и сравнение с мировым уровнем

Дата: 2026-09-29 · версия в репозитории: 0.8.1 · ветка: `arena/01a0ecbf-azrail-os`

Состояние на начало работы: 79 файлов TypeScript (15 068 строк), 46 тестовых
файлов, 1052 теста — все зелёные, typecheck чистый. Это не проект, который
«не работает». Это проект, у которого **работающий бэкенд шире, чем
интерфейс, через который к нему можно добраться**. Разбор ниже в основном об
этом.

Сразу о двух вещах, которых в этой сессии не было:

- **Архив `dark-mnmll-pulse-os-cloudflare-1.0.0.zip` к сообщению не
  приложен.** Ни в рабочей области, ни в репозитории его нет. Всё, что
  написано ниже, относится к содержимому `mnmllpulse/azrail-os`. Если в
  архиве есть код, которого здесь нет, — его нужно приложить, он не
  учитывался.
- **HTML-файл с глобусом тоже не приложен.** Глобус написан с нуля (см.
  раздел 5), а не перенесён из вашего файла. Если у вас есть конкретный
  макет — пришлите, подгоню под него.

**Что здесь объективно сильно.** Идемпотентность запросов, отдельный контур
допуска миссий, крон-сборщик зависших, чекпойнты, учёт токенов с явным
разделением «измерено / неизвестно», реестр моделей со ссылкой на источник у
каждой записи, централизованная авторизация одной функцией, запрет
самодеплоя. Этого нет ни у v0, ни у Bolt, ни у Lovable — они решают другую
задачу, но перечисленное — не догоняющие фичи, а то, где проект уже впереди.

### 1.3 Интерфейс (`public/`) — главная проблема, найденная разбором

До этой сессии интерфейсов было **четыре**, и они не были связаны:

| Файл | Размер | Ключ токена в браузере | Что умеет |
|---|---|---|---|
| `index.html` | 264 КБ | `azrail_token` | задача, чат, журнал, песочница, история, умения, служебное |
| `classic.html` | 71 КБ | `azrail_token` | полные формы: ветки, репозитории, параметры |
| `ultimate.html` + `.css` + `.js` | 33 + 9 + 14 КБ | `azrail_ultimate_token` | создание миссии, студии, политика моделей |
| `control.html` + `.js` | 6 + 5 КБ | `azrail_control_token` | метрики, копии, аккаунты, тарифы, бюджеты |

**Три разных ключа в трёх разных хранилищах.** Чтобы посмотреть метрики
проекта, за который только что запустил миссию, нужно было открыть другую
страницу и ввести тот же токен ещё раз. Это не неудобство оформления, это
разрыв в модели продукта: система вела себя как три разных продукта на одном
домене.

**И это ещё не главное.** Главное — маршруты, к которым из главного экрана не
вело ничего:

| Маршрут | Есть на сервере | Читался главным экраном (до) |
|---|---|---|
| `GET /api/metrics` | да | **нет** |
| `POST/GET /api/backups`, `/api/backups/restore` | да | **нет** |
| `POST /api/mission/recover` | да | **нет** |
| `GET /api/projects/:id/memory` + `DELETE …/:cat/:key` | да | **нет** |
| `GET /api/projects/:id/versions` + `POST …/restore` | да | **нет** |
| `GET /api/projects/:id/history` | да | **нет** |
| `GET /api/routing-settings`, `POST /api/admin/routing-settings` | да | **нет** |
| `GET /api/model-catalog` | да | **нет** |
| весь `/api/admin/*` (аккаунты, разрешения, владельцы, тарифы, бюджеты) | да | **нет** |

Двенадцать групп маршрутов, написанных, покрытых тестами и отдаваемых в
пустоту. **Работающий код, к которому нет дороги из интерфейса, для
пользователя неотличим от ненаписанного.**

## 2. Слабые места

### 2.1 Два файла-гиганта

`core/execution-engine.ts` — 1739 строк, `index.ts` — 1192 строки и 55 веток
маршрутизации в одной функции `fetch`. Порядок веток здесь несёт смысл
(защита маршрутов зависит от позиции, и это уже один раз ломалось — есть
регрессионный тест). Любая вставка в середину — риск. Правильное лечение:
таблица маршрутов вместо лестницы `if`, с сохранением того же порядка.
*Не сделано в этой сессии: это правка, которую нельзя проверить иначе как
живым трафиком, и делать её вместе с UI-изменениями — значит смешать два
источника риска.*

### 2.2 Ответ приходит одним куском

Ни `ReadableStream`, ни `text/event-stream` в проекте нет. `/api/chat`
возвращает готовый JSON. WebSocket есть, но только для событий миссии, не для
токенов ответа. На практике это 3–15 секунд пустого экрана на каждый вопрос.
**Это самый заметный разрыв с v0, Bolt и Lovable** — у них текст начинает
идти через 300–600 мс. Функционально они не лучше; ощущается их интерфейс
принципиально живее.

### 2.3 Нечего показать из того, что построено

В интерфейсе нет файлового дерева проекта, нет редактора, нет предпросмотра
собранного приложения. `Песочница` запускает вставленный вручную HTML — это
не то же самое, что «вижу дерево файлов, правлю строку, перезагружаю
предпросмотр». У Bolt это ядро продукта (WebContainers), у v0 — превью
компонента рядом с чатом. Бэкенд для этого готов: `workspace.ts`,
`file-window.ts`, `versions.ts`, R2 — всё есть. Не хватает экрана.

### 2.4 Разрешения писались вслепую — **исправлено**

`project_permissions` читалась только изнутри исполнения. Выдать и отозвать
возможность через API было можно, **узнать текущее состояние — нет**.
Администратор нажимал «Выдать», на экране не менялось ничего, и проверить
результат можно было только запуском задачи, то есть узнать о собственной
настройке по отказу. Добавлен `GET /api/admin/permissions?projectId=`,
список возможностей сведён в единственную константу `PROJECT_CAPABILITIES`
(до этого тот же перечень был выписан строкой в трёх местах и разошёлся бы
при первом добавлении новой возможности).

### 2.5 Списки без страниц

`accounts LIMIT 100`, `model_prices LIMIT 200`, `backups LIMIT 50`,
`getHistory LIMIT 20`. Потолок молчаливый: на 101-м аккаунте список просто
перестанет быть полным, и никто об этом не узнает. Лечится курсором и
признаком «есть ещё» в ответе.

### 2.6 `CORS_ORIGIN = "*"` при авторизации по Bearer

С токеном в заголовке `*` не открывает прямую дыру (браузер не приложит
заголовок сам), но снимает последний барьер при любой будущей ошибке —
например, если когда-нибудь появится авторизация по cookie. Для боевого
домена значение должно быть конкретным.

### 2.7 Потолок контейнеров

`max_instances = 2`. Это ограничение параллелизма, и оно **не является
денежным лимитом**: контейнеры тарифицируются за время работы. Комментарий в
`wrangler.toml` об этом честно предупреждает, но таймаутов и контроля
тарификации рядом нет.

### 2.8 Зависимости — **исправлено**

`ip-address@10.5.0` (транзитивно: `agents` → MCP SDK → `express-rate-limit`)
с уязвимостью SSRF через диапазон NAT64. Обновлено, боевой аудит теперь
`found 0 vulnerabilities`. Оставшиеся три предупреждения — внутри `wrangler`,
это инструмент разработки, в рантайм не попадает.

### 2.9 Один HTML на 270 КБ

`index.html` — 270 КБ (70 КБ в gzip) одним файлом: разметка, стили и скрипт
вместе. Плюс: ноль внешних запросов, страница поднимается без сети — это
осознанное и защищённое тестами свойство. Минус: нет ни разбиения на части,
ни кеширования по отдельности, ни подгрузки по требованию. На быстрой связи
незаметно; на 3G это полторы секунды до первой отрисовки.

## 3. Топ-5 платформ мирового уровня: что у них и чего нет у нас

Сравнение по состоянию рынка на 2026 год.

### v0 (Vercel)
Самый чистый UI-вывод в категории: React/Next.js + Tailwind + shadcn/ui,
код проходит ревью без переписывания; Figma-to-code — первоклассная функция;
деплой в один клик [1](https://altar.io/lovable-vs-bolt-vs-v0-vs-replit-vs-base44/).
В 2026 добавлены полноценная песочница, git-панель и интеграции с базами,
но full-stack остаётся более слабой половиной
[2](https://appcoding.com/ai-app-builders-reviewed-lovable-base44-bolt-replit-and-v0-compared/).
Расплата — привязка к экосистеме Vercel и токенная тарификация, где стоимость
запроса неизвестна до его выполнения [1](https://altar.io/lovable-vs-bolt-vs-v0-vs-replit-vs-base44/).

**Чему учиться:** качеству вывода как отдельной дисциплине и предсказуемости
результата. **Где мы уже впереди:** учёт денег. У нас стоимость считается по
фактическим токенам с явным разделением «измерено / неизвестно», и бюджет
можно задать на проект, миссию и аккаунт.

### Bolt.new (StackBlitz)
Полный Node.js в браузере через WebContainers, мультифреймворковость (React,
Vue, Svelte, Astro), самый быстрый путь «идея → работающий URL», Figma-импорт
и Expo для мобильного [1](https://altar.io/lovable-vs-bolt-vs-v0-vs-replit-vs-base44/).
Около 28 минут до рабочего прототипа — лучший показатель в замерах
[3](https://till-freitag.com/en/blog/vibe-coding-tools-comparison).
Слабости: ограничения браузерной песочницы для не-JS рантаймов и выгорание
токенов на больших приложениях [4](https://daily.dev/blog/ai-app-builder-cursor-vs-lovable-vs-bolt-vs-v0-which-should-you-pick/).

**Чему учиться:** среде исполнения прямо в интерфейсе — дерево файлов,
терминал, живой предпросмотр. Это пункт 2.3. **Где мы впереди:** у нас
настоящая серверная песочница на контейнерах (node + python + git), а не
браузерная эмуляция — не-JS задачи ей по силам.

### Lovable
Лучший внешний вид «из коробки» для нетехнического основателя, визуальный
редактор, импорт из Figma, синхронизация с GitHub, выбор между Supabase и
собственным управляемым бэкендом [2](https://appcoding.com/ai-app-builders-reviewed-lovable-base44-bolt-replit-and-v0-compared/).
Буксует на сложной бизнес-логике и уходит в циклы багов
[4](https://daily.dev/blog/ai-app-builder-cursor-vs-lovable-vs-bolt-vs-v0-which-should-you-pick/).

**Чему учиться:** «чистому первому экрану» — один ввод, никаких настроек до
первого результата. **Где мы впереди:** ровно там, где Lovable буксует. У нас
есть планировщик, рефлексия, проверка по канону, откат при регрессии и
бенчмарк, измеряющий долю реально починенных тестов. Это и есть защита от
«цикла багов», и она измерима.

### Replit Agent 3
Самая автономная платформа списка: из текстового описания — схема,
авторизация, фронтенд и деплой, обычно меньше чем за час; порождает
суб-агентов, пишет и запускает собственные тесты, 50+ языков, более 160
сторонних сервисов через OpenInt [2](https://appcoding.com/ai-app-builders-reviewed-lovable-base44-bolt-replit-and-v0-compared/),
[5](https://lovable.dev/guides/best-ai-app-builders).
Полный IDE в браузере с терминалом и контролем версий — «стеклянный ящик»
вместо чёрного [5](https://lovable.dev/guides/best-ai-app-builders).
Расплата — острые края: платформа даёт достаточно верёвки, чтобы снести
собственную базу, и это уже случалось
[2](https://appcoding.com/ai-app-builders-reviewed-lovable-base44-bolt-replit-and-v0-compared/).

**Чему учиться:** широте интеграций. **Где мы впереди:** ровно на тех самых
острых краях. Блокировка проекта, идемпотентность, чекпойнты, резервные
копии, восстановление версии, которое **не коммитит и не деплоит**, и прямой
запрет самодеплоя. Снести себе базу через AZRAIL заметно труднее — и это
архитектурное решение, а не случайность.

### Cursor
Форк VS Code с ИИ на уровне архитектуры: понимание репозитория целиком,
многофайловые правки, автономный режим агента, который пишет, тестирует и
отлаживает в локальном окружении разработчика
[5](https://lovable.dev/guides/best-ai-app-builders). Лучший выбор для
существующей кодовой базы, но без встроенного бэкенда и деплоя
[4](https://daily.dev/blog/ai-app-builder-cursor-vs-lovable-vs-bolt-vs-v0-which-should-you-pick/).

**Чему учиться:** работе с существующим репозиторием как с первым классом
задач. **Где мы впереди:** у нас есть `repo-map.ts`, `file-window.ts` и
`scout.ts` — заготовки того же самого, плюс Git Agent и сканирование
уязвимостей, которых у Cursor нет.

первым местом по ощущениям он не станет, сколько бы ни было правильного
внутри.

## 4. Что сделано в этой сессии

### 4.1 Четыре интерфейса сведены в один

`public/index.html` стал единственной оболочкой. Добавлены пять разделов, и
каждый обращается к настоящим маршрутам — заглушек нет ни одной:

- **Студии и лаборатории** — `/api/agents` с человеческими именами, которые
  раньше жили только в `control.js`. Студия из словаря, которой нет на
  сервере, помечается отдельно: расхождение реестров видно здесь, а не по
  отказу задачи.
- **Обзор проекта** — единый идентификатор проекта на все разделы;
  `/api/metrics` (включая отдельную цифру «стоимость неизвестна»);
  резервные копии — снять, показать, восстановить; спасение зависшей миссии
  через `/api/mission/recover`.
- **Память и версии** — `/api/projects/:id/memory` с удалением факта
  (единственный способ отменить неверный вывод, который иначе применяется ко
  всем будущим задачам проекта), `/versions` с восстановлением и показом
  состава, `/history`.
- **Модели и маршрут** — политика `/api/routing-settings` с объяснением,
  какого именно из трёх условий не хватает для включения платных моделей;
  живой каталог Cloudflare `/api/model-catalog` с пометкой «нет в реестре»;
  сетка реестра с причиной недоступности у каждой модели.
- **Администрирование** — аккаунты, разрешения (теперь с чтением состояния),
  владельцы ресурсов, тарифы и бюджеты. Пункт меню появляется только у роли
  `admin`: сервер откажет остальным на каждом маршруте раздела, и видимая
  кнопка была бы обещанием несуществующего.

Прежние экраны (`ultimate.html`, `control.html`, `classic.html`) остались
доступны ссылками — ничего не удалено.

### 4.2 Планета

Каркасный шар с меридианами и параллелями, три орбитальных кольца с разными
наклонами, спутник на каждом кольце, узлы на поверхности. Canvas 2D, ни одной
зависимости, ни одного сетевого запроса.

Скорость — 0.055 рад/с, полный оборот около двух минут. Это не произвол:
движение в углу экрана, заметное боковым зрением, перетягивает внимание с
поля ввода, ради которого сюда и приходят.

**Две границы, поставленные намеренно, потому что на них уже наступали.**
Трёхмерная Земля здесь была раньше и была удалена владельцем: она тянула
three.js с внешнего адреса (без сети страница не поднималась) и занимала на
телефоне весь первый экран. Поэтому: (1) ноль внешних ресурсов — проверяется
тестом; (2) на экране уже 860 пикселей планета уходит из потока за текст —
**высота шапки не меняется ни на пиксель**, тоже проверяется тестом. При
выключенном движении шар рисуется один раз в статичной позе, а не исчезает:
пустой прямоугольник читается как незагрузившаяся картинка, а не как уважение
к настройке.

### 4.3 Исправления в бэкенде

- `GET /api/admin/permissions?projectId=` — закрыт разрыв 2.4.
- `PROJECT_CAPABILITIES` — единый источник списка возможностей вместо трёх
  копий строкой.
- `ip-address` обновлён, боевой аудит чист.

### 4.4 Проверки

32 новых теста в `tests/globe-and-modules.test.ts`. Они закрывают не
оформление, а то, что уже ломалось в этом проекте: маршрут отвалился от
экрана, обработчик потерял разметку, пункт меню ведёт в никуда, данные с
сервера попали в разметку строкой, необратимое действие без подтверждения,
планета снова разрослась на телефоне.

**Итог:** `typecheck` чистый, **1084 теста зелёные** (было 1052),
`npm audit --omit=dev` — 0 уязвимостей.

## 5. Что осталось до первого места

По убыванию влияния на ощущение продукта.

1. **Потоковый ответ.** `ReadableStream` в `/api/chat`, посимвольная отрисовка
   в интерфейсе. Самая заметная разница с v0/Bolt/Lovable. Оценка: 2–3 дня.
2. **Рабочая область на экране.** Дерево файлов из `workspace.ts`, редактор,
   предпросмотр в iframe, привязка к версиям. Бэкенд готов полностью, нужен
   экран. Оценка: 1–2 недели.
3. **Таблица маршрутов вместо 55 веток `if`** в `index.ts` — с сохранением
   текущего порядка, потому что от него зависит защита.
4. **Страницы в списках** (2.5) — курсор и признак «есть ещё».
5. **Конкретный `CORS_ORIGIN`** для боевого домена (2.6).
6. **Разбиение `index.html`** на части с раздельным кешированием — но только
   не ценой свойства «работает без сети», оно дороже.
