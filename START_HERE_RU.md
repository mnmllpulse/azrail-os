# AZRAIL OS 0.8.1 Ultimate

Этот пакет объединяет проверенные локально изменения кода и архитектуру следующего уровня. Он не является готовым развёртыванием всех заявленных функций.

## Исправления 0.8.1

Подробный отчёт: `docs/audit-2026-09-26/AUDIT_RU.md`. Сборка 0.8.1 исправляет Ultimate на телефоне, переходы миссий, подсказки, пути и резервные копии, платёжные резервы, WebSocket-доступ и чтение GitHub.

`public/ultimate.html` теперь содержит CSS и JavaScript внутри. Для просмотра можно извлечь **один этот файл** и открыть в браузере. Локальное открытие не запускает ИИ: для работы перейдите на HTTPS-адрес вашего развёрнутого AZRAIL. После правок `ultimate.css`/`ultimate.js` выполните `npm run build:ui`.

Перед обновлением сервера примените миграцию 007. Старые KV-подсказки не переносятся; новые резервные копии используют формат v2. Ограничения старых путей и порядок обновления описаны в новом отчёте.

## Что изменилось

Сторонние и платные модельные маршруты выключены по умолчанию на сервере. Проверка действует и при ручном выборе модели, повторе и работе вложенного агента. Бесплатный список вызывает AI binding без Gateway. Для ON нужны настройки владельца, месячный бюджет и свежая цена модели. Резерв по месяцу общий для параллельных платных текстовых вызовов. Добавлены живой каталог, простой экран задач, настройка режима, шаблон Free-установки и отказ при сломанном валидаторе ответа. Сохранены аккаунты, роли, владение ресурсами, журнал миссий и копии файлов из предыдущих изменений.

## Обновление существующей установки

1. Сохраните D1, R2 и текущую версию Worker. Работайте сначала со staging.
2. Нужен Node.js 24. Выполните `npm ci` и `npm run check`.
3. Проверьте ресурсы `wrangler.toml`. Их ID из старого архива нельзя считать ресурсами любого нового аккаунта. Этот конфиг содержит платную контейнерную песочницу.
4. Скрипт `npm run db:migrate -- --local` только инспектирует локальную схему. Для подготовки плана по удалённой D1 используется `--remote`; конфиг выбирается через `--config путь.toml`.
5. Запись в удалённую D1 выполняется отдельно: `npm run db:migrate -- --remote --apply`. Скрипт сначала экспортирует D1, затем применяет недостающие изменения 002–007. R2 сохраняется отдельно. Команда не запускает deployment Worker.
6. Перед публикацией проверьте план миграций, доступы и бюджет. Развёртывание — отдельная операция в выбранном аккаунте; платный Sandbox требует Docker и Workers Paid.
7. После публикации пройдите вход, миссию, повтор с тем же ключом, отмену, восстановление и модельный OFF/ON. Скрипт `npm run smoke` проверяет только доступные read-only endpoints; ему нужны URL и токен согласно scripts/smoke.mjs.

Не применяйте все исторические SQL подряд к новой базе: `schema.sql` уже содержит актуальные таблицы. Не удаляйте таблицы для отката кода.

## Новая бесплатная установка

`wrangler.free.example.toml` предназначен для отдельного нового Worker. Укажите собственные D1/KV/R2 ресурсы, примените актуальную schema.sql к выбранной базе и задайте серверный AZRAIL_TOKEN как secret. Конфиг исключает Container/Sandbox binding и закрепляет AZRAIL_FORCE_FREE=true. Не применяйте его поверх существующего Paid Worker с миграцией Sandbox.

Полный Linux runtime в этом профиле отсутствует. Доступны облачное ядро в рамках квот, генерация файлов и интерфейс; локальный runner пока только спроектирован. У R2 и других продуктов отдельная тарификация. Нулевой бюджет внешних моделей не означает нулевой счёт всех сервисов аккаунта.

Для будущего включения Gateway владелец сознательно снимает FORCE_FREE в конфигурации, настраивает Gateway и цены, затем задаёт бюджет и включает режим в интерфейсе. Никакой смены режима по признаку телефона или ПК нет.
