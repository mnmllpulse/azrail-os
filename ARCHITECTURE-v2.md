# AZRAIL v2 — путь к универсальности

Записано 2026-08-24. Это план, а не описание сделанного.
Сделанного здесь пока нет ничего.

## Вводные

Два ответа, от которых всё зависит:

**Пользователь один — владелец.** Отпадает многопользовательность,
регистрации, тарифы, изоляция чужих данных. Не пишем и не сопровождаем.

Но правило «понятно за 10 секунд» остаётся. Только адресат другой: не
случайный гость, а сам владелец через три месяца, забывший устройство
собственной системы. Это опаснее — чужой уйдёт к конкуренту, свой бросит
то, что сам построил.

**AZRAIL строит DARK MNMLL PULSE OS и становится ей.** Значит должен
уметь править собственный код. Не как отдельную функцию, а как обычную
задачу.

## Почему нынешняя архитектура упирается в потолок

Восемь агентов, у каждого свой код и свой промпт:

```
architect  125   code       174   ui         226   git        278
deploy     117   security   135   qa         283   evolution  277
                                              всего ≈ 1400 строк
```

Каждая новая способность — девятый агент, десятый, тридцатый. Через год
половина сломана, и никто не помнит зачем они.

«Уметь всё» так не достигается. Список удлиняется, универсальности нет.

## Перестройка

### Было

```
задача → классифицировать → выбрать агента → фиксированный промпт
       → один вызов модели → вернуть результат
```

Один проход. Ошибся — вернул ошибку.

### Станет

```
задача → цикл:
           модель выбирает инструмент
           инструмент выполняется
           модель смотрит результат
           повторяет, пока не готово
       → самопроверка
       → результат
```

### Инструменты — общие, и их мало

| Инструмент | Что делает | Откуда берётся |
|---|---|---|
| `read_file` | читает файл проекта | есть, `source-reader.ts` |
| `write_file` | пишет файл | **нет** |
| `run_tests` | прогоняет vitest | **нет** |
| `git_branch_commit` | ветка + коммит | есть частично, `git-agent.ts` |
| `open_pr` | открывает PR | **нет** |
| `search_web` | ищет в сети | **нет** |
| `call_model` | вызывает модель | есть, `model-router.ts` |
| `generate_image` | картинка | **нет**, но это один вызов модели |

Восемь инструментов покрывают и «нарисуй картинку», и «собери SaaS».
Разница между ними — не в наборе возможностей, а в числе итераций цикла.

### Агенты становятся промптами

`security-agent.ts` (135 строк кода) → `prompts/security.md` (текст).

Тот же цикл, та же машинерия, другая инструкция. Добавить роль = добавить
файл с текстом, а не модуль с кодом.

Оценка: ≈1400 строк агентов → ≈300 строк цикла + восемь текстовых файлов.

## Жёсткое правило: самомодификация только через PR

**AZRAIL не разворачивает себя. Никогда.**

Если он выкатит сломанную версию — он мёртв. Чинить придётся с телефона,
где `wrangler` не запускается (проверено: падает на Android ARM64). Останется
только пушить вслепую в GitHub и ждать сборку, не видя ошибок.

Разрешено:
- читать свой код
- писать в отдельную ветку
- открывать PR с описанием, что и зачем
- прогонять тесты в этой ветке

Запрещено:
- писать в `main`
- вызывать deploy
- трогать `wrangler.toml`, секреты, `.npmrc`

Слияние делает человек. Это не бюрократия — это единственное, что стоит
между владельцем и кирпичом, который не починить с телефона.

## Порядок работ

Каждый шаг оставляет систему рабочей. Не «большой переезд», а замена
деталей на ходу.

**1. Инструменты рядом со старым кодом.**
Добавить `write_file`, `run_tests`, `open_pr`. Агентов не трогать.
Проверка: инструменты вызываются из тестов, старые маршруты зелёные.

**2. Цикл на одной задаче.**
Написать цикл и пустить через него ТОЛЬКО `review_repo`. Остальные семь
агентов работают по-старому. Проверка: обзор репозитория проходит через
цикл и даёт результат не хуже прежнего.

**3. Перенос ролей в промпты, по одной.**
Начать с самой простой (`architect`), закончить самой сложной (`qa`).
После каждой — тесты. Проверка: удалённый агент не сломал ничего.

**4. Самомодификация под запретом на деплой.**
Дать циклу право писать в ветку и открывать PR на собственный репозиторий.
Проверка: AZRAIL открывает PR с осмысленной правкой, `main` не тронут.

**5. Картинки и остальное.**
На этом этапе — просто ещё один инструмент. Никакого нового агента.

## Чего в плане намеренно нет

**Стриминга.** Секундомер в интерфейсе закрывает главную боль (экран не
выглядит зависшим). Стриминг лучше, но это отдельная работа, и она не
блокирует ничего.

**Памяти интерфейса между заходами.** Обновил страницу — результат пропал.
Чинится, но позже.

**Показа фактической цены.** Сейчас в интерфейсе стоит оценка «примерно
6 центов». Настоящий расход Cloudflare возвращает в ответе — показывать
надо его, а не догадку.

## Что проверить до начала

Ни одна модель ещё не отвечала в проде. Реестр собран, слаги сверены,
цены известны — но это теория. Первый живой вызов может вскрыть что-то,
что перечеркнёт часть плана.

Сначала вызов, потом перестройка.
