# Развёртывание через GitHub → Cloudflare

Версия 1.0.0-cf · 28 сентября 2026 · Этот документ описывает действия владельца. Публикация, изменение DNS и обращения к вашим платным моделям в ходе переноса не выполнялись.

## 1. Проверьте, к какому аккаунту относятся ресурсы

В корневом `wrangler.toml` оставлены идентификаторы из вашего исходного архива:

| Параметр | Значение |
|---|---|
| Worker | `mnmll-pulse-core` |
| D1 binding | `DB` |
| D1 name | `dark-planet-db` |
| D1 ID | `f59a6c68-f2d1-4ec9-9b2b-3bb0b4002669` |
| R2 binding / bucket | `R2` / `dark-planet-assets` |
| Workers AI binding | `AI` |
| Static Assets binding | `ASSETS` → `dist/` |

Проверьте существование D1 и R2 в выбранном аккаунте. Если это чужие/старые ресурсы или нужна чистая база, создайте новые D1/R2 в Dashboard и замените `database_name`, `database_id`, `bucket_name`. Наличие записи в конфигурации не означает, что ресурс уже создан или проверен.

Три зоны `mnmllpulse.com`, `mnmllpulse.org`, `pulse-labs.org` должны быть активны в вашем Cloudflare. Конфигурация направляет на этот Worker **все пути** этих трёх имён. Если там уже работают сайты, сначала сохраните их текущую конфигурацию и выберите момент переключения. Custom Domain нельзя создать поверх существующего CNAME; конфликтующий маршрут/запись разбирается отдельно, без массового удаления DNS. `www` автоматически не добавлен: при необходимости настройте редирект `www` → корневой домен.

## 2. Подготовьте GitHub

1. Распакуйте ZIP. В корне репозитория должны лежать `package.json`, `package-lock.json`, `wrangler.toml`, `src/`, `worker/`, `shared/`, `cloudflare/`, `scripts/`, `public/`, `tests/`, `system_docs/`.
2. Загружайте содержимое проекта, а не ZIP одним файлом. Сохраните `.github/`, `.node-version`, `.gitignore`.
3. Не загружайте `node_modules/`, `.work/`, `.wrangler/`, заполненные `.env`/`.dev.vars`, резервные копии базы. Они исключены из поставляемого ZIP.
4. Рабочая ветка — `main` (или ваша выбранная production-ветка). GitHub workflow только проверяет код и не содержит Cloudflare-секретов.

## 3. Подключите Workers Builds

В Cloudflare → Workers & Pages создайте Worker из GitHub-репозитория либо подключите Git к существующему `mnmll-pulse-core`.

| Настройка | Значение |
|---|---|
| Root directory | корень репозитория |
| Production branch | `main` либо выбранная вами ветка |
| Node | `24` — зафиксирован в `.node-version` |
| Build command | `npm run check` |
| Production deploy command | `npm run deploy:ci` |
| Non-production / PR deployment | отключить до создания отдельной staging-конфигурации |

Cloudflare устанавливает зависимости, затем выполняет проверку и сборку. `deploy:ci` сначала применяет D1-миграции, затем выполняет `wrangler deploy`. При ошибке миграции публикация не запускается. Миграции не запускаются в обычных тестах или сборке.

Workers Builds может создать build API token автоматически. Для команды, включающей D1-миграции, проверьте также разрешение на изменение нужной D1. Для публикации нужны права на Worker и привязку custom domains в нужных зонах. Если выбрали собственный token, ограничьте его вашим аккаунтом/зонами и добавьте необходимые права на D1, Workers Scripts, Workers Routes и доступ к используемым ресурсам. Не вставляйте deploy token в frontend или runtime API формы. При ошибке permission denied исправляйте конкретное недостающее разрешение в build token.

Если начальная автоматическая публикация выполнилась до задания секрета, API останется закрытым. После задания секрета повторите deploy.

## 4. Задайте секрет владельца

В Worker → Settings → Variables and Secrets создайте **Secret** `OWNER_ACCESS_KEY`. Используйте случайное значение, например 64 hex-символа из менеджера паролей или локальной команды:

```sh
openssl rand -hex 32
```

Это ключ входа в приложение. Сохраните его в своём менеджере паролей. Не добавляйте его в Git, `VITE_*`, build output или текст публичного issue.

Сессия живёт 12 часов. Cookie защищена `HttpOnly`, `Secure`, `SameSite=Strict` и не имеет общего `Domain`. Поэтому на `.com`, `.org` и `pulse-labs.org` нужно войти отдельно. Замена `OWNER_ACCESS_KEY` отзывает старые сессии. Публичной регистрации и роли обычного пользователя пока нет.

## 5. Сохраните существующую базу перед первым обновлением

Если используете уже существующую D1, сначала сделайте её экспорт через Dashboard или авторизованный Wrangler:

```sh
mkdir -p backups
npx wrangler d1 export DB --remote --output backups/pre-cloudflare-migration.sql
```

Сохраните экспорт отдельно от репозитория. Initial migration создаёт только таблицы с префиксом `pulse_` и индексами; старые таблицы не удаляет. Учёт миграций — `pulse_schema_migrations`. Автоматического переноса старых Firebase-данных, локальных файлов сервера или browser localStorage в D1 нет. Для этого нужны отдельные экспорты старых данных: в ZIP исходников их нет.

При чистой базе резервировать ещё нечего. Первый `deploy:ci` создаст схему в уже существующем D1-ресурсе.

## 6. Дневные лимиты и сторонние модели

По умолчанию в конфигурации:

```toml
DAILY_AI_LIMIT = "30"
ALLOW_THIRD_PARTY_MODELS = "false"
EXTERNAL_DAILY_LIMIT = "0"
```

Это **число попыток генерации**, а не нейроны и не денежный бюджет. Неудачные попытки также учитываются. Лимит общий для владельца и трёх доменов; AI-счётчик сбрасывается в 00:00 UTC. Одна текстовая совместная работа может потратить несколько попыток. При исчерпании лимита запрос отклоняется, платного fallback нет. Значение `DAILY_AI_LIMIT="0"` выключает генерации.

Workers AI имеет бесплатную квоту 10 000 Neurons в день. На Workers Paid превышение этой квоты может оплачиваться. R2, D1, Workers и Builds имеют свои отдельные лимиты и условия. Выключение сторонних моделей **не является гарантией нулевого счёта Cloudflare**.

Для optional Google-адаптера нужны все условия:

1. Secret `GEMINI_API_KEY` в runtime Worker.
2. `ALLOW_THIRD_PARTY_MODELS="true"` в `wrangler.toml`.
3. Ненулевой `EXTERNAL_DAILY_LIMIT`, от 1 до 100.
4. Доступный вашему аккаунту реальный ID в `GEMINI_TEXT_MODEL`, `GEMINI_VIDEO_MODEL` или `GEMINI_MUSIC_MODEL`.
5. Включение владельцем в панели `/studio/billing`.

Текстовый endpoint принимает настроенный `GEMINI_TEXT_MODEL`, но общий UI-каталог этой версии показывает четыре нативных адаптера. Каталог всех сторонних моделей и AI Gateway Unified Billing здесь не реализованы. Music-адаптер требует, чтобы выбранная модель возвращала audio inline через используемый API; специальный realtime music API не реализован. Без реальной provider-проверки не считайте эту интеграцию готовой музыкальной генерацией.

## 7. Необязательные подключения

- `DEPLOY_HOOK_URL`: секретный официальный Workers Builds Deploy Hook. Нужен только для кнопки запуска сборки внутри приложения. Обычный Git push → Builds работает без него. Ответ «queued» означает принятую сборку; результат смотрите в Cloudflare.
- `CLOUDFLARE_READ_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`: отдельный ограниченный token чтения для списка зон/Worker. Для AI, сессий и файлов не нужен. Не используйте здесь deploy token с широкими правами.
- Cron `17 * * * *`: удаляет истёкшие сессии/старые лимиты и помечает зависшие попытки генерации. Это не расписание Beatport и не автономная фабрика задач.

## 8. Проверьте после первого deploy

1. На каждом домене откройте `/api/health`: ожидается JSON с версией `1.0.0-cf`. Это liveness; доступность D1 и моделей проверяется отдельными шагами.
2. Откройте `/api/site`: проверьте соответствующую роль домена.
3. Без входа `/api/user-status` должен вернуть 401; `/dashboard` должен переводить на вход.
4. Войдите своим ключом. Обновите страницу; сессия должна сохраниться. Неверный ключ не должен давать доступ.
5. Выполните один короткий текстовый запрос и проверьте сохранение истории. Эта проверка потребляет вашу AI-квоту.
6. Загрузите небольшой текстовый файл через работающий upload-сценарий. Скачивание требует входа; HTML выдаётся вложением.
7. Проверьте `/studio/deploy` и `/studio/billing`. Сторонние модели должны оставаться выключенными, пока вы их явно не настроили.
8. Выйдите, снова откройте приватный API — ожидается 401. Повторите вход на остальных двух доменах.
9. На телефоне проверьте вход, меню, студии и клавиатуру. Автоматическая браузерная проверка в среде подготовки была заблокирована до запуска страницы; визуальная приёмка остаётся обязательной.

## 9. Откат

Сохраните git commit и версию Worker до обновления. При сбое верните прошлую рабочую версию Worker через Cloudflare. Новые таблицы `pulse_` не нужно удалять для отката. Если повреждены данные, восстанавливайте их из сохранённого экспорта/доступного D1 recovery после проверки. Кнопки «автоматически всё восстановить» в этой версии нет.
